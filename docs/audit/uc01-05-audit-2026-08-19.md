per the `overflow-x: auto` design, and no test fails, but it undercut the use case's purpose.

`position: sticky`, so they stay on screen while the later columns scroll; the pinned reference column is
narrowed to 7.5rem so it earns its place at 1366px, and carries a hairline that reads as "there is more
table to the right". **Proven by** `the row number and item reference stay in the viewport at 1366x768`,
which scrolls the table fully right *first* and then asserts both boxes are inside the viewport — the
assertion is meaningless unless the table really scrolled, so the check also asserts `scrollLeft > 0`.

### FINDING A1 — my own audit branch silently grew the main suite
The first post-remediation reconciliation reported **155 tests in 9 files** against 149 declared in
`e2e/*.spec.ts`. The ninth file was `e2e/audit/walkthrough.spec.ts` — the Phase 6 evidence harness, which
the main config picked up because `testDir` is `./e2e`. It passed, so nothing went red, and the only reason
