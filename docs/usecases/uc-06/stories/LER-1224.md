# LER-1224 — Narrative treatment in the flat renderer

_UC-06 Legal Language Assistance · epic: `docs/usecases/uc-06/epic.md` · PRD: `docs/usecases/uc-06/prd.md`_

_DevOps Bot ticket **LER-1224** (Story, To Do) · build order: story 02 of 15, stage 1._

## User Story
As a defence solicitor completing an MG5, I want the same narrative help the MG11 gets, so that the case summary is not a second-class citizen with no assistance at all.

## Acceptance Criteria
- Given a declared narrative field on any form, when the flat renderer draws it, then it renders the shared narrative component — amber highlighting, word count and flag summary — not a plain textarea.
- Given MG5, when it opens, then its four narrative fields each carry the narrative treatment.
- Given MG11, when it opens through the wizard, then the narrative behaves exactly as it did before this story — same marks, same word count, same tooltips.
- Given a non-narrative textarea, when it renders, then it is a plain textarea with no highlight layer.
- Given the suite, when it runs, then UC-03's existing hearsay and opinion checks still pass unchanged.

## Notes & Constraints

- **This is the largest piece of the epic and it is engine work, not panel work.**
  `NarrativeField` is referenced today only from `mg11-wizard.html`; MG5 goes through the flat
  `DynamicForm`, so its five textareas have no highlighting at all. The DoD names MG5, so the component has
  to be reachable from the shared renderer.
- One component, two entry points: the wizard keeps passing it explicitly, the renderer picks it up from the
  declared flag. Do not fork it — a second copy means every future fix twice.
- Watch the date-field lesson: a suffix nested inside another control-flow block does not reach
  `mat-form-field`'s suffix slot. Expect the same class of surprise here and give the branch its own case.

- Pure core: `libs/shared/src/lib/language-assistance.ts` (new) and UC-03's existing
  `narrative-flags.ts`. Panel: `apps/web/.../language-assistant/`. Narrative component:
  `apps/web/.../narrative-field/`.
- **Nothing is ever auto-applied.** The control's value may change ONLY inside the Insert handler. Any other
  write path is the defect this UC exists to prevent.
- **No invented phrasing.** A prompt may offer `insertText` only when its provenance is `documented` with a
  cited source — enforced by `canProposeVerbatim()` at runtime AND by `npm run conformance`, both.
- **Additive only:** never rename or delete a field id; bump `templateVersion` on any template whose fields
  change; run `npm run orphan-scan` around any id change.
- Reuse UC-03's detector and highlight backdrop; do not fork them. Its five hearsay/opinion patterns must
  behave identically afterwards.
- Amber is advisory; **red stays reserved for UC-07 sensitive material**. Design tokens only.
- After changing `libs/shared`, **restart the API** — the nest watcher does not pick up shared-lib rebuilds.
- Full mechanism and business rules: `docs/usecases/uc-06/prd.md` (§4 and §8).
