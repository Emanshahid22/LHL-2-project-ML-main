# LER-1237 — QA: Definition of Done checks

_UC-06 Legal Language Assistance · epic: `docs/usecases/uc-06/epic.md` · PRD: `docs/usecases/uc-06/prd.md`_

_DevOps Bot ticket **LER-1237** (Story, To Do) · build order: story 15 of 15, stage 5._

## User Story
As a delivery lead, I want one automated check per Definition of Done line, so that UC-06 is provably finished rather than asserted to be.

## Acceptance Criteria
- Given DoD line 1, when the suite runs, then a check asserts the panel appears for a narrative on **MG5** and on **MG11**, and does not appear on a non-narrative textarea.
- Given DoD line 2, when the suite runs, then a check renders prompts and asserts the narrative control is byte-identical with no Insert pressed.
- Given DoD line 3, when the suite runs, then a check inserts mid-text, asserts the resulting string and caret position, and reads the `LANGUAGE_SUGGESTION_INSERTED` audit row back from the database.
- Given DoD line 4, when the suite runs, then a check fails the assistance route and asserts no visible error and zero console errors.
- Given the epic's own bar, when the suite runs, then checks prove no unattributable wording is insertable, that `STANDARD_PHRASES` ships empty, and that the assistance module has no draft write path.
- Given the guardrails, when `npm run conformance` and `npm run orphan-scan` run, then both pass, with a planted-defect self-test for each new structural rule.
- Given the whole suite, when it runs, then every pre-existing check stays green — including UC-03's hearsay and opinion checks — and every `data-testid` is intact.

## Notes & Constraints

- Cite each check by spec file and test name in the PR, mapped to its DoD line — the format
  `docs/acceptance-mapping.md` uses.
- Clean up test data: snapshot draft ids before, log created ids via `E2E_DRAFT_LOG`, delete only the
  difference. The user's own drafts must survive.
- If a DoD line cannot be fully proven, record it as a coverage gap in `open-questions.md` rather than
  citing a check that does not cover it. UC-03's PDF-dependent criteria are the precedent.

- Pure core: `libs/shared/src/lib/language-assistance.ts` (new) and UC-03's existing
  `narrative-flags.ts`. Panel: `apps/web/.../language-assistant/`. Narrative component:
  `apps/web/.../narrative-field/`.
- **Nothing is ever auto-applied.** The control's value may change ONLY inside the Insert handler. Any other
  write path is the defect this UC exists to prevent.
- **No invented phrasing.** A prompt may offer `insertText` only when its provenance is `documented` with a
  cited source — enforced by `canProposeVerbatim()` at runtime AND by `npm run conformance`, both.
- **Additive only:** never rename or delete a field id; bump `templateVersion` on any template whose fields
  change; run `npm run orphan-scan` around any id change.
- Reuse UC-03's detector and highlight backdrop; do not fork them. Its five hearsay/opinion patterns must
  behave identically afterwards.
- Amber is advisory; **red stays reserved for UC-07 sensitive material**. Design tokens only.
- After changing `libs/shared`, **restart the API** — the nest watcher does not pick up shared-lib rebuilds.
- Full mechanism and business rules: `docs/usecases/uc-06/prd.md` (§4 and §8).

## Definition of Done
- Delivered against the acceptance criteria above
- `npm run test:e2e` green and both builds pass
- `npm run conformance` and `npm run orphan-scan` pass
- Every existing `data-testid` intact
- Test drafts cleaned from `apps/api/prisma/dev.db`
