# LER-1227 — Standard phrase suggestions, provenance-gated

_UC-06 Legal Language Assistance · epic: `docs/usecases/uc-06/epic.md` · PRD: `docs/usecases/uc-06/prd.md`_

_DevOps Bot ticket **LER-1227** (Story, To Do) · build order: story 05 of 15, stage 2._

## User Story
As a defence solicitor, I want standard phrasing offered for common evidential descriptions, so that routine passages are worded consistently — but never wording that somebody made up.

## Acceptance Criteria
- Given the registry, when it ships, then every entry carries a pattern that triggers it, the phrasing, a `provenance` and a `source`.
- Given an entry whose provenance is not `documented`, or which cites no source, when the panel renders it, then it offers NO insertable wording.
- Given `STANDARD_PHRASES` as delivered, when it is inspected, then it is **empty** — the scope asks for standard phrasing but supplies none, and inventing courtroom wording is the one thing this epic must not do.
- Given an entry added later with a real citation, when it triggers, then the panel offers it to insert with no code change.
- Given any attempt to ship insertable wording without a source, when `npm run conformance` runs, then it fails.

## Notes & Constraints

- **Shipping this registry empty is the deliverable, not a shortfall.** The shape, the gate and the tests
  land so a practitioner can fill it in a pull request that adds data and no code.
- Why the bar is higher here than in UC-05: an unsourced validation rule shows a wrong hint, which a user
  can ignore. An unsourced *phrase* is one button-press from becoming the witness's signed words.
- Filling it is the largest single thing a human must supply for this UC to deliver its headline value —
  `open-questions.md` Q1.

- Pure core: `libs/shared/src/lib/language-assistance.ts` (new) and UC-03's existing
  `narrative-flags.ts`. Panel: `apps/web/.../language-assistant/`. Narrative component:
  `apps/web/.../narrative-field/`.
- **Nothing is ever auto-applied.** The control's value may change ONLY inside the Insert handler. Any other
  write path is the defect this UC exists to prevent.
- **No invented phrasing.** A prompt may offer `insertText` only when its provenance is `documented` with a
  cited source — enforced by `canProposeVerbatim()` at runtime AND by `npm run conformance`, both.
- **Additive only:** never rename or delete a field id; bump `templateVersion` on any template whose fields
  change; run `npm run orphan-scan` around any id change.
- Reuse UC-03's detector and highlight backdrop; do not fork them. Its five hearsay/opinion patterns must
  behave identically afterwards.
- Amber is advisory; **red stays reserved for UC-07 sensitive material**. Design tokens only.
- After changing `libs/shared`, **restart the API** — the nest watcher does not pick up shared-lib rebuilds.
- Full mechanism and business rules: `docs/usecases/uc-06/prd.md` (§4 and §8).
