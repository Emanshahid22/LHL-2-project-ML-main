# LER-1233 — The assistance service boundary

_UC-06 Legal Language Assistance · epic: `docs/usecases/uc-06/epic.md` · PRD: `docs/usecases/uc-06/prd.md`_

_DevOps Bot ticket **LER-1233** (Story, To Do) · build order: story 11 of 15, stage 4._

## User Story
As a defence solicitor, I need certainty that whatever generates suggestions cannot touch my draft, so that assistance can never become an unattributed edit.

## Acceptance Criteria
- Given the assistance module, when it is inspected, then it has no Prisma client, no drafts service, and no route that mutates a draft.
- Given the suite, when it runs, then a source-level guard asserts that absence, so an accidental future write path fails the build rather than shipping.
- Given the service returns a prompt carrying wording but no source, when the response is processed, then the wording is stripped and only the observation may show.
- Given the service returns a malformed prompt, when the response is processed, then that prompt is dropped and the remainder are shown.
- Given `LANGUAGE_ASSIST_URL` is unset, when the app runs, then the module is not registered and the panel works from the in-process rules alone.
- Given prompt text from the service, when it is rendered, then it is rendered as text and never as markup.

## Notes & Constraints

- The service takes text and returns candidate prompts. One direction, always. It is the difference between
  "an assistant suggested this and the solicitor accepted it" and "something edited a witness statement".
- Everything it returns is UNTRUSTED DATA: validate the shape, strip unattributable wording, render as text.
- Bounded: short timeout, response size cap, no retries. It must never fail a request the user made.
- **Narrative text is case content.** Pointing this at a hosted model sends a witness's account to a third
  party, which is why unconfigured is the default and why the choice is a decision-maker question
  (`open-questions.md` Q6), not an implementation detail.

- Pure core: `libs/shared/src/lib/language-assistance.ts` (new) and UC-03's existing
  `narrative-flags.ts`. Panel: `apps/web/.../language-assistant/`. Narrative component:
  `apps/web/.../narrative-field/`.
- **Nothing is ever auto-applied.** The control's value may change ONLY inside the Insert handler. Any other
  write path is the defect this UC exists to prevent.
- **No invented phrasing.** A prompt may offer `insertText` only when its provenance is `documented` with a
  cited source — enforced by `canProposeVerbatim()` at runtime AND by `npm run conformance`, both.
- **Additive only:** never rename or delete a field id; bump `templateVersion` on any template whose fields
  change; run `npm run orphan-scan` around any id change.
- Reuse UC-03's detector and highlight backdrop; do not fork them. Its five hearsay/opinion patterns must
  behave identically afterwards.
- Amber is advisory; **red stays reserved for UC-07 sensitive material**. Design tokens only.
- After changing `libs/shared`, **restart the API** — the nest watcher does not pick up shared-lib rebuilds.
- Full mechanism and business rules: `docs/usecases/uc-06/prd.md` (§4 and §8).
