# LER-1236 — Panel accessibility

_UC-06 Legal Language Assistance · epic: `docs/usecases/uc-06/epic.md` · PRD: `docs/usecases/uc-06/prd.md`_

_DevOps Bot ticket **LER-1236** (Story, To Do) · build order: story 14 of 15, stage 5._

## User Story
As a solicitor using a keyboard or a screen reader, I want the assistant usable without a mouse, so that the help is actually available to me.

## Acceptance Criteria
- Given the panel, when I navigate by keyboard, then it is reachable and every Insert and Dismiss control is operable by Enter or Space.
- Given a prompt appears while I am typing, when it appears, then focus stays in the narrative — the panel never steals it.
- Given the panel, when a screen reader encounters it, then it is a labelled landmark and new prompts are announced politely rather than assertively.
- Given every control in the panel, when focused, then it shows a visible focus indicator meeting AA contrast.
- Given the amber marks in the text, when they convey a flag, then the same information is available as text in the panel — colour is never the only carrier.

## Notes & Constraints

- Public-sector context: AA contrast and visible focus are requirements, not niceties.
- The colour-is-not-the-only-carrier point matters twice here, because amber marks in the text are exactly
  the kind of signal a colour-blind user would miss; the panel entry is the accessible equivalent.

- Pure core: `libs/shared/src/lib/language-assistance.ts` (new) and UC-03's existing
  `narrative-flags.ts`. Panel: `apps/web/.../language-assistant/`. Narrative component:
  `apps/web/.../narrative-field/`.
- **Nothing is ever auto-applied.** The control's value may change ONLY inside the Insert handler. Any other
  write path is the defect this UC exists to prevent.
- **No invented phrasing.** A prompt may offer `insertText` only when its provenance is `documented` with a
  cited source — enforced by `canProposeVerbatim()` at runtime AND by `npm run conformance`, both.
- **Additive only:** never rename or delete a field id; bump `templateVersion` on any template whose fields
  change; run `npm run orphan-scan` around any id change.
- Reuse UC-03's detector and highlight backdrop; do not fork them. Its five hearsay/opinion patterns must
  behave identically afterwards.
- Amber is advisory; **red stays reserved for UC-07 sensitive material**. Design tokens only.
- After changing `libs/shared`, **restart the API** — the nest watcher does not pick up shared-lib rebuilds.
- Full mechanism and business rules: `docs/usecases/uc-06/prd.md` (§4 and §8).
