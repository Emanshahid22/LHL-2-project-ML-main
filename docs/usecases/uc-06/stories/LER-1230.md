# LER-1230 — Insert is audited

_UC-06 Legal Language Assistance · epic: `docs/usecases/uc-06/epic.md` · PRD: `docs/usecases/uc-06/prd.md`_

_DevOps Bot ticket **LER-1230** (Story, To Do) · build order: story 08 of 15, stage 3._

## User Story
As a defence solicitor, I want the fact that I accepted a suggestion recorded, so that the file shows how the wording came about if it is ever questioned.

## Acceptance Criteria
- Given an insertion, when it happens, then a `LANGUAGE_SUGGESTION_INSERTED` audit row is written.
- Given that row, when it is inspected, then it records the field id, the prompt id, the prompt kind and the **suggestion text** — the scope's post-condition requires the wording to be logged.
- Given that row, when it is inspected, then it contains **no part of the narrative** — the witness's own
  words are never recorded, only the assistant's.

  _Amended during the build._ This criterion first read "neither the narrative text nor the inserted
  wording". The scope's post-condition is explicit — *"All Insert actions logged in the form audit trail
  with the suggestion text"* — and the scope is the source of truth. The suggestion text is the
  assistant's own wording, carrying a citation, so it is product text rather than case content; the
  narrative itself still never leaves the draft. See `open-questions.md` Q7.
- Given the audit write fails, when it does, then the insertion still stands and nothing is surfaced to the user.
- Given the scope's Definition of Done line "Insert action correctly places text at cursor position and logs the action in the audit trail", when the suite runs, then a check proves both halves together.

## Notes & Constraints

- `AuditAction` gains one member. Follow the existing rule that an audit failure is logged and never
  breaks a user action — the insertion is the user's, and losing it because a log line failed would be
  indefensible.
- The no-content rule is asserted, not assumed: the check reads the row back and asserts the narrative text
  does not appear in it.

- Pure core: `libs/shared/src/lib/language-assistance.ts` (new) and UC-03's existing
  `narrative-flags.ts`. Panel: `apps/web/.../language-assistant/`. Narrative component:
  `apps/web/.../narrative-field/`.
- **Nothing is ever auto-applied.** The control's value may change ONLY inside the Insert handler. Any other
  write path is the defect this UC exists to prevent.
- **No invented phrasing.** A prompt may offer `insertText` only when its provenance is `documented` with a
  cited source — enforced by `canProposeVerbatim()` at runtime AND by `npm run conformance`, both.
- **Additive only:** never rename or delete a field id; bump `templateVersion` on any template whose fields
  change; run `npm run orphan-scan` around any id change.
- Reuse UC-03's detector and highlight backdrop; do not fork them. Its five hearsay/opinion patterns must
  behave identically afterwards.
- Amber is advisory; **red stays reserved for UC-07 sensitive material**. Design tokens only.
- After changing `libs/shared`, **restart the API** — the nest watcher does not pick up shared-lib rebuilds.
- Full mechanism and business rules: `docs/usecases/uc-06/prd.md` (§4 and §8).
