# LER-1234 — Graceful degradation

_UC-06 Legal Language Assistance · epic: `docs/usecases/uc-06/epic.md` · PRD: `docs/usecases/uc-06/prd.md`_

_DevOps Bot ticket **LER-1234** (Story, To Do) · build order: story 12 of 15, stage 4._

## User Story
As a defence solicitor, I want the assistant to go quiet when it cannot work, so that infrastructure problems never interrupt me writing a statement.

## Acceptance Criteria
- Given the assistance service is unavailable, timing out or erroring, when the narrative is analysed,
  then the panel states *"Language assistance temporarily unavailable"* — the scope's own Error Handling
  wording — and there is **no error, no snackbar and no banner**.

  _Amended during the build._ This first read "the panel shows no error, no snackbar and no banner",
  which the scope's Error Handling line is more specific than: it names the notice the panel must show.
  A quiet statement of fact inside the panel is not an error surfaced to the user, and the check still
  asserts zero console errors alongside it.
- Given that state, when the browser console is read, then there are **no console errors**.
- Given that state, when I keep typing, then the in-process informal and completeness rules still work — the panel degrades to less, not to nothing.
- Given that state, when I save the draft, then saving behaves exactly as normal.
- Given the scope's Definition of Done line "Panel degrades gracefully when language AI service is unavailable — no errors surfaced to user", when the suite runs, then a check proves it with the service route failing.

## Notes & Constraints

- "No errors surfaced to user" is literal and includes the console: a page full of red console noise is a
  bug report waiting to happen and it is exactly what a reviewer will look at.
- Because the local rules are pure and in-process, an unavailable service costs the user the phrase library
  and nothing else. That is the design paying off — state it in the PR.

- Pure core: `libs/shared/src/lib/language-assistance.ts` (new) and UC-03's existing
  `narrative-flags.ts`. Panel: `apps/web/.../language-assistant/`. Narrative component:
  `apps/web/.../narrative-field/`.
- **Nothing is ever auto-applied.** The control's value may change ONLY inside the Insert handler. Any other
  write path is the defect this UC exists to prevent.
- **No invented phrasing.** A prompt may offer `insertText` only when its provenance is `documented` with a
  cited source — enforced by `canProposeVerbatim()` at runtime AND by `npm run conformance`, both.
- **Additive only:** never rename or delete a field id; bump `templateVersion` on any template whose fields
  change; run `npm run orphan-scan` around any id change.
- Reuse UC-03's detector and highlight backdrop; do not fork them. Its five hearsay/opinion patterns must
  behave identically afterwards.
- Amber is advisory; **red stays reserved for UC-07 sensitive material**. Design tokens only.
- After changing `libs/shared`, **restart the API** — the nest watcher does not pick up shared-lib rebuilds.
- Full mechanism and business rules: `docs/usecases/uc-06/prd.md` (§4 and §8).
