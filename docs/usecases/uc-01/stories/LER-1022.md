## User Story
As a defence solicitor, I want the form to render every box the template declares, grouped as the form groups them, so that what I see on screen corresponds to the paper form.

## Acceptance Criteria
- Given a draft for any of the eleven forms, when it opens, then every field the template declares is rendered, under its section heading where it has one.
  - Covered by: e2e/mg4-charge-sheet.spec.ts › `every field renders, grouped into its sections`
- Given each of the eleven templates in turn, when it is fetched and rendered, then it loads without error.
  - Covered by: e2e/uk-dates.spec.ts › `every date field across all 11 forms uses the shared datepicker` (opens each template in turn)
  - Covered by: e2e/uc01-form-selection.spec.ts › `picker offers all 11 MG forms`
- Given a template whose field set is not practitioner-verified, when the form opens, then the header carries a persistent "Unverified template" chip, so the form never reads as filing-ready.
  - Covered by: e2e/mg4-charge-sheet.spec.ts › `the unverified indicator shows on the form header`
  - Covered by: e2e/mg4-charge-sheet.spec.ts › `a verified template shows no indicator`

## Notes & Constraints

- One renderer for every form: `apps/web/src/app/shared/dynamic-form/`. Adding a form is a data
  change in `libs/shared`, not a component.
- `templateVersion` is recorded on the draft but **not honoured** — `form-fill-page.ts` loads by
  `formCode`, so an older draft renders against the current field set. See `open-questions.md`.

- Template model: `libs/shared/src/lib/form-template.types.ts` and `form-templates.ts`.
- **Additive only:** a field id is permanent — `valuesJson` is keyed by id, so a rename strands live
  draft data on the next autosave (1.5s). `npm run orphan-scan` checks this.
- Every `data-testid` is load-bearing; MG1 is the fixture form for around 20 assertions.
- After changing `libs/shared`, restart the API — the nest watcher does not pick up shared-lib rebuilds.
