## User Story
As a defence solicitor, I want to reopen a form exactly as I left it, so that a form spanning several sittings is one piece of work rather than several.

## Acceptance Criteria
- Given a saved draft, when I find it in the work queue, then the row identifies it by form and case and offers a way back in.
  - Covered by: e2e/uc01-form-selection.spec.ts › `draft appears in the work queue and resumes with its saved values`
  - Covered by: e2e/dashboard.spec.ts › `rows remain full-row links that resume the draft`
- Given I reopen a draft, when the form renders, then every value I saved is present in its field.
  - Covered by: e2e/uc01-form-selection.spec.ts › `draft appears in the work queue and resumes with its saved values`
- Given several drafts in the queue, when I use one row's Continue, then I resume that row's draft and not another.
  - Covered by: e2e/dashboard.spec.ts › `Continue resumes the draft belonging to its own row`
- Given a stored ISO date, when the form renders it, then it displays as DD/MM/YYYY rather than in storage format.
  - Covered by: e2e/uk-dates.spec.ts › `a stored ISO date displays as DD/MM/YYYY`

## Notes & Constraints

- The queue is the user's own drafts only, `DRAFT` status, most recently touched first.
- Resume renders against the **current** template because `templateVersion` is not honoured; safe only
  while template changes stay additive.

- Template model: `libs/shared/src/lib/form-template.types.ts` and `form-templates.ts`.
- **Additive only:** a field id is permanent — `valuesJson` is keyed by id, so a rename strands live
  draft data on the next autosave (1.5s). `npm run orphan-scan` checks this.
- Every `data-testid` is load-bearing; MG1 is the fixture form for around 20 assertions.
- After changing `libs/shared`, restart the API — the nest watcher does not pick up shared-lib rebuilds.
