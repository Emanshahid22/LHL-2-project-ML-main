## User Story
As a defence solicitor unfamiliar with a particular MG form, I want an explanation attached to each box, so that I can complete it correctly without leaving the form to find guidance.

## Acceptance Criteria
- Given any rendered field, when the form loads, then a `?` control sits with it, labelled for the field it belongs to.
  - Covered by: e2e/uc01-form-selection.spec.ts › `required fields are marked and contextual help expands`
- Given a field's `?` control, when I activate it, then the template's `helpText` for that field is revealed in place.
  - Covered by: e2e/uc01-form-selection.spec.ts › `required fields are marked and contextual help expands`

## Notes & Constraints

- `helpText` is required by the conformance gate: `npm run conformance` fails any template with a
  field that has no help text, and an assessed template must clear a per-field and average length floor.
  Contextual help is a UC-01 acceptance behaviour, so its absence is treated as structural, not stylistic.

- Template model: `libs/shared/src/lib/form-template.types.ts` and `form-templates.ts`.
- **Additive only:** a field id is permanent — `valuesJson` is keyed by id, so a rename strands live
  draft data on the next autosave (1.5s). `npm run orphan-scan` checks this.
- Every `data-testid` is load-bearing; MG1 is the fixture form for around 20 assertions.
- After changing `libs/shared`, restart the API — the nest watcher does not pick up shared-lib rebuilds.
