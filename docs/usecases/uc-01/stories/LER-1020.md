## User Story
As a defence solicitor, I want to say explicitly whether a form belongs to a case, so that a form I start for a one-off purpose is not silently attached to the wrong file.

## Acceptance Criteria
- Given I pick a form, when the picker responds, then a "Link to a case?" dialog appears naming the form I chose.
  - Covered by: e2e/uc01-form-selection.spec.ts › `picking a form opens the "Link to a case?" dialog`
- Given the dialog is open, when I cancel, then no draft is created — the decision is not made for me.
  - Covered by: e2e/uc01-form-selection.spec.ts › `cancelling the dialog starts no draft`
- Given the dialog is open, when I choose Standalone, then the draft is created unlinked and the form header shows a Standalone chip.
  - Covered by: e2e/uc01-form-selection.spec.ts › `starting a standalone form navigates to the draft and shows the Standalone chip`
- Given the dialog is open, when I choose a case, then the draft is created linked and the form header shows that case's URN and defendant.
  - Covered by: e2e/uc01-form-selection.spec.ts › `starting a case-linked form carries the case onto the form`

## Notes & Constraints

- `POST /api/drafts { formCode, caseId? }`; `caseId: null` is the standalone signal.
- The link decision is what makes UC-02 possible or not: a standalone draft has nothing to populate from
  and `POST /drafts/:id/autofill` rejects it.

- Template model: `libs/shared/src/lib/form-template.types.ts` and `form-templates.ts`.
- **Additive only:** a field id is permanent — `valuesJson` is keyed by id, so a rename strands live
  draft data on the next autosave (1.5s). `npm run orphan-scan` checks this.
- Every `data-testid` is load-bearing; MG1 is the fixture form for around 20 assertions.
- After changing `libs/shared`, restart the API — the nest watcher does not pick up shared-lib rebuilds.
