## User Story
As a defence solicitor, I want my typing kept without pressing save, so that a closed laptop or a lost connection does not cost me the form.

## Acceptance Criteria
- Given I am typing into a form, when I stop, then the values are persisted shortly afterwards without any explicit save.
  - Covered by: e2e/uc01-form-selection.spec.ts › `debounced autosave persists without an explicit save`
- Given a form with unsaved changes, when the save is in flight, then the header says so, and afterwards it reports when it saved.
  - Covered by: e2e/uc01-form-selection.spec.ts › `debounced autosave persists without an explicit save`
- Given an untouched date field, when the form autosaves, then it saves as an empty string rather than as a spurious value.
  - Covered by: e2e/uk-dates.spec.ts › `an untouched date field still saves as an empty string`

## Notes & Constraints

- Debounce is 1.5s from the last change, and a save is skipped entirely when the serialised values
  match what was last saved. A save already in flight queues the next rather than racing it.
- The debounce interval is also why a renamed field id is dangerous: the next autosave can write back the
  pruned object and the stranded value is gone.

- Template model: `libs/shared/src/lib/form-template.types.ts` and `form-templates.ts`.
- **Additive only:** a field id is permanent — `valuesJson` is keyed by id, so a rename strands live
  draft data on the next autosave (1.5s). `npm run orphan-scan` checks this.
- Every `data-testid` is load-bearing; MG1 is the fixture form for around 20 assertions.
- After changing `libs/shared`, restart the API — the nest watcher does not pick up shared-lib rebuilds.
