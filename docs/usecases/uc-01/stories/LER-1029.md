## User Story
As a defence solicitor, I want a failure to fetch a form to explain itself and offer a retry, so that a transient problem does not look like a broken product.

## Acceptance Criteria
- Given the template list cannot be fetched, when the dashboard loads, then an explanatory panel with Retry appears instead of an empty picker.
  - Covered by: e2e/uc01-form-selection.spec.ts › `template load failure on the dashboard offers Retry`
- Given a draft cannot be fetched, when I open it, then an explanatory panel with Retry appears instead of a blank form.
  - Covered by: e2e/uc01-form-selection.spec.ts › `draft load failure offers Retry`
- Given the retry succeeds, when the content loads, then the page continues normally with no reload required.
  - Covered by: e2e/uc01-form-selection.spec.ts › `template load failure on the dashboard offers Retry`

## Notes & Constraints

- The rest of the dashboard keeps working when only the picker's fetch fails; the failure is scoped to
  the section that could not load.

- Template model: `libs/shared/src/lib/form-template.types.ts` and `form-templates.ts`.
- **Additive only:** a field id is permanent — `valuesJson` is keyed by id, so a rename strands live
  draft data on the next autosave (1.5s). `npm run orphan-scan` checks this.
- Every `data-testid` is load-bearing; MG1 is the fixture form for around 20 assertions.
- After changing `libs/shared`, restart the API — the nest watcher does not pick up shared-lib rebuilds.
