## User Story
As a defence solicitor, I want to save a part-finished form and be told it saved, so that I can stop work with confidence rather than hoping.

## Acceptance Criteria
- Given a form with unsaved changes, when I press Save draft, then the values are persisted and a confirmation appears.
  - Covered by: e2e/uc01-form-selection.spec.ts › `explicit Save draft persists and confirms with a snackbar`
- Given a save has completed, when I look at the header, then the save status shows the time it was saved rather than staying ambiguous.
  - Covered by: e2e/uc01-form-selection.spec.ts › `explicit Save draft persists and confirms with a snackbar`
- Given another tab has saved the same draft, when my stale save is submitted, then it is rejected with 409 and the newer work is not overwritten.
  - Covered by: e2e/uc01-form-selection.spec.ts › `a stale save is rejected with 409 and does not overwrite newer work`

## Notes & Constraints

- `PATCH /api/drafts/:id { values, baseVersion }`; the update applies only while the stored
  `version` still matches `baseVersion`. The whole values object is replaced, so two tabs cannot
  interleave field-by-field.
- A `DRAFT_SAVED` audit event is written on every successful save.

- Template model: `libs/shared/src/lib/form-template.types.ts` and `form-templates.ts`.
- **Additive only:** a field id is permanent — `valuesJson` is keyed by id, so a rename strands live
  draft data on the next autosave (1.5s). `npm run orphan-scan` checks this.
- Every `data-testid` is load-bearing; MG1 is the fixture form for around 20 assertions.
- After changing `libs/shared`, restart the API — the nest watcher does not pick up shared-lib rebuilds.
