## User Story
As a defence solicitor, I want to see how much of the form is still outstanding, so that I know whether it is ready without re-reading every box.

## Acceptance Criteria
- Given a form with M required fields, when it opens, then the header reads "0 of M required fields completed".
  - Covered by: e2e/uc01-form-selection.spec.ts › `header progress reports N of M required fields and advances as they are filled`
- Given the progress indicator, when I complete a required field, then the count advances immediately without a save or a reload.
  - Covered by: e2e/uc01-form-selection.spec.ts › `header progress reports N of M required fields and advances as they are filled`
- Given a draft in the work queue, when the queue renders, then that row shows its own required-field progress computed from its template.
  - Covered by: e2e/dashboard.spec.ts › `each row shows required-field progress computed from the template`

## Notes & Constraints

- One definition of completeness (`isFieldValueComplete`) is shared by the header, the queue row and
  the MG11 wizard's per-step count, so the three can never disagree.
- Progress requires the control to be **valid as well as non-empty**, so an invalid value cannot inflate
  the count.

- Template model: `libs/shared/src/lib/form-template.types.ts` and `form-templates.ts`.
- **Additive only:** a field id is permanent — `valuesJson` is keyed by id, so a rename strands live
  draft data on the next autosave (1.5s). `npm run orphan-scan` checks this.
- Every `data-testid` is load-bearing; MG1 is the fixture form for around 20 assertions.
- After changing `libs/shared`, restart the API — the nest watcher does not pick up shared-lib rebuilds.
