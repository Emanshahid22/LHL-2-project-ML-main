## User Story
As a defence solicitor working inside a case, I want to start a form without being asked which case it belongs to, so that the product does not ask me something it already knows.

## Acceptance Criteria
- Given I am on a case detail page, when I choose "Complete MG Form", then I am asked only which form — not which case.
  - Covered by: e2e/uc01-form-selection.spec.ts › `case detail "Complete MG Form" starts a draft pre-linked to that case`
- Given I pick a form from there, when the draft opens, then it is already linked to the case I started from.
  - Covered by: e2e/uc01-form-selection.spec.ts › `case detail "Complete MG Form" starts a draft pre-linked to that case`
- Given the dashboard case list, when I click a case row, then I reach that case's detail page, so this route into form creation is reachable.
  - Covered by: e2e/dashboard.spec.ts › `case rows still link to the case detail page`

## Notes & Constraints

- `form-picker-dialog` (case detail) and `case-link-dialog` (dashboard) are separate components
  precisely because the questions differ: one asks "which form", the other "which form, then which case".

- Template model: `libs/shared/src/lib/form-template.types.ts` and `form-templates.ts`.
- **Additive only:** a field id is permanent — `valuesJson` is keyed by id, so a rename strands live
  draft data on the next autosave (1.5s). `npm run orphan-scan` checks this.
- Every `data-testid` is load-bearing; MG1 is the fixture form for around 20 assertions.
- After changing `libs/shared`, restart the API — the nest watcher does not pick up shared-lib rebuilds.
