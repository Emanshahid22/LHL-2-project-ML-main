## User Story
As a defence solicitor, I want every MG form I might need presented where I can see it, so that starting the right form is the first thing I can do rather than something I scroll to find.

## Acceptance Criteria
- Given I open the dashboard, when the page loads, then a form picker lists all eleven MG templates, each showing the code, name and description the template itself declares.
  - Covered by: e2e/uc01-form-selection.spec.ts › `picker offers all 11 MG forms`
  - Covered by: e2e/dashboard.spec.ts › `picker cards carry the real code, name and description from the template`
- Given the picker is rendered, when I inspect a card, then it carries `[data-form-code]` so the card is addressable by form rather than by position.
  - Covered by: e2e/dashboard.spec.ts › `cards keep [data-form-code] and render code, name and description`
- Given a standard laptop screen, when the dashboard loads, then the picker is the first section and is fully visible without scrolling.
  - Covered by: e2e/dashboard.spec.ts › `form picker is the first section, ahead of the work queue and cases`
  - Covered by: e2e/dashboard.spec.ts › `picker is fully visible without scrolling at 1366x768`
  - Covered by: e2e/dashboard.spec.ts › `picker is fully visible without scrolling at 1920x1080`
- Given a wide screen, when the picker lays out, then all eleven cards sit in a compact grid rather than a long column.
  - Covered by: e2e/dashboard.spec.ts › `all 11 cards lay out 4-up on a wide screen`
- Given a description too long for its card, when I hover it, then the full text is available as a tooltip rather than being lost to truncation.
  - Covered by: e2e/dashboard.spec.ts › `card descriptions expose full text via tooltip when truncated`

## Notes & Constraints

- The list comes from `GET /api/form-templates`; there is no hardcoded form list in the web app.
- Per-form icons are hand-drawn inline SVG on purpose. An icon font that fails to load renders icon
  *names* as visible text and pollutes assertions.
- The picker's position is a regression risk with history: it was originally 1332px down a 2349px page
  and sank further as drafts accumulated, which is why two viewport sizes are asserted.

- Template model: `libs/shared/src/lib/form-template.types.ts` and `form-templates.ts`.
- **Additive only:** a field id is permanent — `valuesJson` is keyed by id, so a rename strands live
  draft data on the next autosave (1.5s). `npm run orphan-scan` checks this.
- Every `data-testid` is load-bearing; MG1 is the fixture form for around 20 assertions.
- After changing `libs/shared`, restart the API — the nest watcher does not pick up shared-lib rebuilds.
