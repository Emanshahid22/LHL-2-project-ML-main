## User Story
As a legal professional, I want to sign in with my own credentials and
have my session managed securely, so that everything I do in the platform
is genuinely mine — the foundation for all access control.

## Acceptance Criteria
- Given valid credentials, when I complete the login flow
  (authorization-code + PKCE against the platform's own authorization
  module), then I receive an HttpOnly Secure SameSite cookie session and
  land in the app; tokens never reach browser JavaScript.
- Given an invalid login, when it fails, then the response is
  content-free and identical for wrong-password and unknown-user, the
  attempt is rate-limited, and LOGIN_FAILED is audited.
- Given an expired, revoked, or logged-out session, when any API call is
  made, then 401 — and the SPA returns to login without losing unsaved
  draft state before the expiry.
- Given logout, when invoked, then the session row is revoked server-side
  and the cookie cleared (audited USER_LOGOUT).
- Given any mutation, when the CSRF header does not match the session's
  secret, then 403 content-free.

## Notes & Constraints
- BFF pattern; Argon2id credentials in their own table; session rows in
  SQLite (additive schema). Lengths/policy/reset per rulings #3/#4/#5.
- The demo guard dies with this story; its `x-user-email` shim must not
  survive anywhere.

## Definition of Done
- Login/logout/expiry/CSRF e2e green; 401 matrix over every controller;
  all 267 existing checks pass through the auth helper with zero handler
  changes.
