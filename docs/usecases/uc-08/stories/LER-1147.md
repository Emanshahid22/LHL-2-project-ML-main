# LER-1147 — Jump to field navigation

_Client ticket **LER-1147** (Story, To Do) · delivering ticket: **LER-1262** · build order: story 08 of 14, stage 3._

## User Story
As a defence solicitor on a long form, I want every finding to take me to the field it is about, so that resolving an issue costs one click, not a scroll hunt.

## Acceptance Criteria
- Given an issue row on a flat-rendered form, when Jump to field is pressed, then the page scrolls to the field's row, focuses its control, and applies a temporary highlight the user can see arrive and fade.
- Given an issue on an MG11 field, when jumping, then the wizard first reveals the step containing that field and then scrolls and highlights — jump works across steps, not only within the visible one.
- Given an issue on a sensitive-declared field the viewer cannot currently see (locked or unconfirmed UC-07 section), when jumping, then the page lands on the sensitive-section block itself — the nearest honest destination.
- Given a form-level issue (e.g. Check 4), when the row renders, then it offers the section-level jump rather than a dead control.

## Notes & Constraints
- Fields already render inside `[data-field-id]` containers; the wizard gains a `revealField`
  input driving `currentStep` — extend, never fork, the UC-03 wizard.
- The highlight is a CSS class on the existing row, removed on a timer; no layout change, no new
  colour tokens.
