# LER-1152 — QA — Definition of Done checks

_UC-08 Form Review & Quality Check · epic: `docs/usecases/uc-08/epic.md` · PRD: `docs/usecases/uc-08/prd.md`_

_Client ticket **LER-1152** (Story, To Do) · delivering ticket: **LER-1268** · build order: story 14 of 14, stage 4._

## User Story
As the project, we want the four UC-08 DoD lines proven by named, repeatable checks, so that an incomplete or inconsistent form provably cannot be finalised.

## Acceptance Criteria
- Given DoD line 1 ("Quality check catches all required field types across 3 different MG form types"), when the suite runs, then checks prove Check 1 on MG6, MG11 and MG3 across text, textarea, date, select, checkbox and group required fields.
- Given DoD line 2 ("'Jump to field' links correctly navigate to and highlight the relevant field"), when the suite runs, then flat-form scroll+focus+highlight, MG11 cross-step reveal, and the UC-07 locked-section fallback are each asserted.
- Given DoD line 3 ("Advisory issues can be acknowledged and bypassed; blocking issues cannot"), when the suite runs, then the advisory path is proven end-to-end (reason recorded in ADVISORY_BYPASSED) AND the blocking half is proven by a REAL HTTP finalise attempt asserting 409 + FINALISE_REJECTED — plus the no-acknowledgement-control assertion on blocking rows.
- Given DoD line 4 ("Cross-reference consistency check correctly flags mismatched exhibit numbers across linked forms"), when the suite runs, then two drafts on one case — MG11 citing an exhibit MG12 does not define — produce the advisory naming the missing reference, and completing MG12 clears it; URN divergence blocks.
- Given the whole suite, when it completes, then every pre-existing check (195) is green, every pre-existing `data-testid` intact, conformance (with the new crossRef self-tests) and orphan-scan pass, and dev.db is restored to 27/66.

## Notes & Constraints
- "Incomplete and inconsistent forms cannot be finalised" — the client ticket's own summary — is
  the property under test; every scenario ends by asking the API, not the button.
- Timeout/partial-results UI is proven via route interception (a crafted review response with an
  incomplete check), since a real timeout cannot be forced honestly in E2E.

## Definition of Done
- Delivered against the acceptance criteria above
- `npm run test:e2e` green and both builds pass
- `npm run conformance` and `npm run orphan-scan` pass
- Every existing `data-testid` intact; the 195-check baseline does not regress
- Test drafts cleaned from `apps/api/prisma/dev.db` (27/66 restored)
