# LER-1141 — Review & Finalise trigger — the single entry point

_UC-08 Form Review & Quality Check · epic: `docs/usecases/uc-08/epic.md` · PRD: `docs/usecases/uc-08/prd.md`_

_Client ticket **LER-1141** (Story, To Do) · delivering ticket: **LER-1255** · build order: story 01 of 14, stage 2._

## User Story
As a defence solicitor, I want one Review & Finalise action that runs the full quality suite, so that finishing a form starts with the product's whole opinion of it, not a hunt through panels.

## Acceptance Criteria
- Given a draft with at least one completed field, when I click "Review & Finalise", then `POST /drafts/:id/review` runs all four checks automatically and the review panel opens with the results — one action, the full suite, every time.
- Given a draft with no completed field, when I look at the trigger, then it is disabled (the scope's pre-condition), and a direct API call to review such a draft is 422.
- Given a FINALISED or ARCHIVED form, when review is requested, then 409 — there is no draft to review.
- Given a clean run (no blocking, no incomplete), when it completes, then the draft's status becomes REVIEWED; a run with findings leaves status untouched.
- Given any run, when it completes, then `QUALITY_CHECK_COMPLETED` is in the audit trail whether it passed or not (LER-1151's evidence-it-ran principle).

## Notes & Constraints
- The engine runs SERVER-side (open-questions F4): Check 3 needs the case's sibling drafts and
  Check 4 the acknowledgement table, and redaction must never distort a result.
- The button lives in the form header beside Save; the live progress signal already knows whether
  a field is complete. No new save-path behaviour (F2).
