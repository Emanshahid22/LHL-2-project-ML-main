# LER-1146 — Issue checklist display

_Client ticket **LER-1146** (Story, To Do) · delivering ticket: **LER-1261** · build order: story 07 of 14, stage 3._

## User Story
As a defence solicitor, I want every finding in one grouped checklist, so that "what is wrong with this form" has a single answer in a single place.

## Acceptance Criteria
- Given a completed review, when the panel renders, then every issue appears in exactly one of three groups — **Blocking**, **Advisory**, **Could not complete** — with a count per group.
- Given any issue row, when it renders, then it shows the finding's description, the affected field's label (or its section label when the field itself is not renderable for this viewer — the UC-07 locked case), and the Jump-to-field control (LER-1147).
- Given a clean run, when the panel renders, then the green "Ready to Finalise" state replaces the checklist (the scope's alt flow).
- Given a run with an incomplete check, when the panel renders, then that check's row says it could not complete, tells the user to verify manually, and the panel states that finalisation stays blocked until a full run completes (open-questions Q5).

## Notes & Constraints
- Blocking rows use the existing danger tokens, advisory rows amber; UC-07's sensitive red only if
  the section itself is on screen. No new colour.
- The closest precedent is `consistency-issues.ts` — an advisory panel that states its own limits.
  The checklist is its finalisation-grade sibling, not a fork of it.
