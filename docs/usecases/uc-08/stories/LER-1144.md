# LER-1144 — Check 3 — cross-form reference consistency

_UC-08 Form Review & Quality Check · epic: `docs/usecases/uc-08/epic.md` · PRD: `docs/usecases/uc-08/prd.md`_

_Client ticket **LER-1144** (Story, To Do) · delivering ticket: **LER-1258** · build order: story 04 of 14, stage 1._

## User Story
As a defence solicitor, I want reference numbers checked across every form on the case, so that the file reads as one case rather than a folder of strangers.

## Acceptance Criteria
- Given two or more of a case's drafts carrying a value for the same case datum (`mapsTo: urn` / `defendantName`), when the suite runs on any of them, then divergent values are a blocking issue naming both forms (one case has one URN — open-questions D1).
- Given exhibit references cited on a `crossRef: cites` field (MG11 `exhibitsReferenced`), when the suite runs, then each cited token absent from the case's `crossRef: defines` fields (MG12 `exhibitEntries`) is an advisory issue naming the missing reference — DoD 4's mismatched exhibit numbers, flagged.
- Given a standalone draft (no case), when the suite runs, then Check 3 reports clean with a note that there were no sibling forms to compare — honesty about what did not run.
- Given consistent references, when the suite runs, then Check 3 is clean.

## Notes & Constraints
- Reference tokens are parsed by the convention BOTH templates' helpText documents ("initials and
  a sequence number, e.g. JS/1", one per line): leading `[A-Za-z]{1,4}/digits` tokens only; prose
  lines ignored entirely (open-questions D2). No NLP, ever.
- The engine takes sibling drafts as INPUT (pure function); the endpoint fetches them user-scoped.
- Pairs with LER-1104, which declares the vocabulary this check consumes.
