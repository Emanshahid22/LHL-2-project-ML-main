## User Story
As a compliance-minded practice, we want finalisation to verify that sensitive-material handling was actually confirmed, so that UC-07's gate reaches all the way to the end of the form's life.

## Acceptance Criteria
- Given a draft whose sensitive section is active (UC-07's derived flag on stored values), when the suite runs, then Check 4 requires at least one recorded HANDLING_INSTRUCTIONS acknowledgement for this draft; absence is a blocking, form-level issue whose row names the MG6D section.
- Given the section is inactive, or the template declares no sensitive section, when the suite runs, then Check 4 is clean — silence is not a default of "confirmed".
- Given a reviewer without the Sensitive Material Access permission, when they review, then the check still computes correctly (server-side, stored values) and its finding names the SECTION, never the content — UC-07's redaction is not weakened by review (open-questions F4).

## Notes & Constraints
- Reads `isSensitiveSectionActive` and the UC-07 `SensitiveAcknowledgement` table; invents nothing.
- Links UC-07 into finalisation — the client ticket's own words. The finalise gate (LER-1150)
  re-checks this at the boundary.
