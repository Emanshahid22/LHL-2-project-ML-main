# LER-1142 — Check 1 — every required field, every field type

_UC-08 Form Review & Quality Check · epic: `docs/usecases/uc-08/epic.md` · PRD: `docs/usecases/uc-08/prd.md`_

_Client ticket **LER-1142** (Story, To Do) · delivering ticket: **LER-1256** · build order: story 02 of 14, stage 1._

## User Story
As a defence solicitor, I want the completeness check to catch every kind of required field I left empty, so that "required" means the same thing at review as it does in the editor.

## Acceptance Criteria
- Given a draft with missing required fields, when the suite runs, then Check 1 reports one blocking issue per missing field — text, textarea, date, select, checkbox (a declaration must be ticked) and repeating group alike — rendered in the blocking (red) group.
- Given a conditionally-required field whose trigger is set (UC-05 `requiredWhen`), when the suite runs, then it is treated exactly as statically required.
- Given a required group with rows whose required columns are incomplete, when the suite runs, then the issue names the group and is blocking (`isGroupValueComplete` — an empty row is not a completed schedule).
- Given sensitive material recorded with an empty MG6D schedule (UC-07), when the suite runs, then the mandatory-section finding appears under Check 1, blocking.
- Given every required field is completed, when the suite runs, then Check 1 reports clean.

## Notes & Constraints
- Pure composition: `requiredFieldIds` + `isConditionallyRequired` + `isFieldValueComplete` +
  `isGroupValueComplete` + `sensitiveScheduleFindings`. No rule is re-implemented (PRD §3).
- DoD 1 is proven across THREE form types (MG6, MG11, MG3) so the field-type coverage claim is
  tested, not assumed.
