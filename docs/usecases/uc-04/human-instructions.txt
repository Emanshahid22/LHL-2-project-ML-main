DESIGNATION INDEPENDENCE — the most important rule on this ticket
- The MG6 designation is disputed and the decision belongs to a decision-maker. This build must NOT
  wait for it and must NOT depend on it.
- Therefore: NO behaviour may branch on the form code. Do not write `code === 'MG6'` anywhere for
  schedule behaviour. The mechanics attach to any template declaring a repeating-group field.
- If the form is later renamed, or the schedule moves to MG6C/MG6D, the mechanics must move with the
  field definition and no behaviour code should change.

Shared-Library Rules
- Reuse the existing type system — do NOT invent a parallel one. Columns are ordinary
  FormFieldDefinitions restricted to scalar types; no nested groups.
- Keep schedule.ts and completeness.ts PURE and framework-free — both apps and the tests share one
  definition of correctness. Thresholds live in completeness.ts, never as literals at call sites.
- ADDITIVE ONLY: never rename or delete an existing field id — values are already stored under those
  ids in FormDraft.valuesJson and renaming strands them on the next autosave (1.5s after a keystroke).
  Run `npm run orphan-scan` before and after any id change.
- Bump templateVersion on any template whose field set changes.
- After changing libs/shared you MUST restart the API: the nest watcher does not pick up libs/shared
  rebuilds, so `npm run dev` needs restarting or the API serves stale templates. The startup log line
  from the MG11 declaration integrity check confirms a fresh boot.

Backend Rules

Correctness Rules specific to this UC — read twice
- The displayed item number is COMPUTED at render from array position. Never store an ordinal. A
  stored counter is the defect this UC exists to prevent: it reattaches audit and sensitivity
  decisions to the wrong material the moment an item is removed mid-schedule.
- Each row's __id is a random uuid, immutable for the life of the row. Edit and reorder must never
  regenerate it. Reorder is a first-class operation, not delete-and-re-add.
- No PII in identifiers — __id must never be derived from a name, reference or file path, because
  these ids reach audit rows and later storage keys.
- Deletion prompts for confirmation BEFORE renumbering; cancel is a true no-op.
- hasSensitiveMaterial is derived, recomputed on every change, and cleared when no sensitive row
  remains. Never user-editable, never latching.
- The completeness check is ADVISORY and must never block saving or navigation. Record its outcome to
  the audit log whether or not it flags — a check that only logs failures cannot prove it ran.
- Sensitive means MARKED, not PROTECTED. UC-07 owns the actual handling. Do not describe this UC in
  code comments, UI copy or the PR as making disclosure safe.
