# LER-1085 — Continuous sequence guarantee

_UC-04 MG6 Unused Material Schedule · epic: `docs/usecases/uc-04/epic.md` · PRD: `docs/usecases/uc-04/prd.md`_

## User Story
As a disclosure officer, I want the schedule numbering to stay continuous and gap-free, so that a reader can tell nothing has been quietly removed.

## Acceptance Criteria
- Given any sequence of add, edit, delete and reorder operations, when the schedule re-renders, then the numbers are always 1..n with no gaps and no duplicates.
- Given an item is deleted from the middle, when the survivors render, then they are renumbered contiguously (a 3-item schedule losing item 2 reads 1, 2).
- Given the scope requires that "gaps are not permitted without explicit deletion", when the implementation is reviewed, then gap-freedom is guaranteed **by construction** (ordinal = position) rather than by a repair routine.
- Given a legacy or malformed value under the group field id (e.g. a string), when the form loads, then it is treated as an empty schedule and reported by `orphan-scan` rather than crashing the renderer.

## Notes & Constraints

- Files: `libs/shared/src/lib/form-template.types.ts` and `form-templates.ts`; renderer in
  `apps/web/src/app/shared/dynamic-form/`; pure logic in `libs/shared/src/lib/schedule.ts`.
- **Designation independence:** no behaviour may branch on the form code — the MG6 designation is
  disputed (`docs/answers/LER-1205-designation-mismatches.md`) and this build must not wait for it.
- **Additive only:** never rename or delete an existing field id; run `npm run orphan-scan` around any
  id change.
- After changing `libs/shared`, **restart the API** — the nest watcher does not pick up shared-lib
  rebuilds and will serve stale templates.
- Full mechanism and business rules: `docs/usecases/uc-04/prd.md` (§4 and §8).
