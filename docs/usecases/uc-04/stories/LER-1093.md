# LER-1093 — QA: Definition of Done checks

_UC-04 MG6 Unused Material Schedule · epic: `docs/usecases/uc-04/epic.md` · PRD: `docs/usecases/uc-04/prd.md`_

## User Story
As the team, I want automated proof of the scope's Definition of Done, so that UC-04 cannot be called complete on inspection alone.

## Acceptance Criteria
- Given the DoD line "MG6 schedule numbering is correct and sequential across add, edit, and delete operations", when the suite runs, then there is a check for **each** of add, edit, delete and reorder asserting numbering is 1..n with no gaps.
- Given the DoD line "Renumbering on deletion prompts user confirmation before executing", when the suite runs, then a check proves the prompt appears **before** the mutation and that cancel is a no-op.
- Given the DoD line "Completeness check fires correctly for 'Complex' cases with fewer than 5 items", when the suite runs, then checks cover 4 items (flagged), 5 items (not flagged) and the summary-only lower bar.
- Given the DoD line "Sensitive classification automatically triggers UC-07 handling without additional user action", when the suite runs, then a check proves the flag is set by classification alone, and cleared when no sensitive row remains.
- Given identity must survive renumbering, when the suite runs, then a check asserts `__id` values are unchanged across delete and reorder.
- Given no ordinal may be stored, when the suite runs, then a check inspects the persisted draft and asserts no stored ordinal exists.
- Given designation independence, when the suite runs, then a check asserts the schedule renders from a template declaring a group regardless of its `code`, and that no source file branches on `'MG6'` for schedule behaviour.
- Given the existing suite, when UC-04 lands, then all pre-existing checks stay green and no `data-testid` has changed.

## Notes & Constraints

- Files: `libs/shared/src/lib/form-template.types.ts` and `form-templates.ts`; renderer in
  `apps/web/src/app/shared/dynamic-form/`; pure logic in `libs/shared/src/lib/schedule.ts`.
- **Designation independence:** no behaviour may branch on the form code — the MG6 designation is
  disputed (`docs/answers/LER-1205-designation-mismatches.md`) and this build must not wait for it.
- **Additive only:** never rename or delete an existing field id; run `npm run orphan-scan` around any
  id change.
- After changing `libs/shared`, **restart the API** — the nest watcher does not pick up shared-lib
  rebuilds and will serve stale templates.
- Full mechanism and business rules: `docs/usecases/uc-04/prd.md` (§4 and §8).

## Definition of Done
- Delivered against the acceptance criteria above
- `npm run test:e2e` green and both builds pass
- `npm run conformance` and `npm run orphan-scan` pass
- Every existing `data-testid` intact
- Test drafts cleaned from `apps/api/prisma/dev.db`
