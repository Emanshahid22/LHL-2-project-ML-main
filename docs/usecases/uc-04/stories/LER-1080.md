# LER-1080 — MG6 definition and layout

_UC-04 MG6 Unused Material Schedule · epic: `docs/usecases/uc-04/epic.md` · PRD: `docs/usecases/uc-04/prd.md`_

## User Story
As a defence solicitor scheduling unused material, I want MG6 to be structured as a numbered schedule rather than a flat form, so that each item of unused material is a row I can add, edit and remove.

## Acceptance Criteria
- Given `FieldType` today is `text | textarea | date | time | number | select | checkbox`, when the type system is extended, then it gains `'group'` and `FormFieldDefinition` gains `columns?: FormFieldDefinition[]`.
- Given a group field, when its columns are declared, then every column is an ordinary `FormFieldDefinition` of a scalar type — a group inside a group is rejected at build time.
- Given MG6 declares the schedule, when the template is saved, then `templateVersion` is bumped and `verification: 'unverified'` is set (no practitioner has signed MG6 off).
- Given `npm run conformance` scores templates, when a group template is scored, then the structural rules understand `group` (columns present, scalar column types, unique column ids) and MG6 passes.
- Given the schedule is declared in the template, when any schedule behaviour is implemented, then no source file branches on the form code to enable it.

## Notes & Constraints
- This story delivers the **engine**, not just MG6: the repeating-group type also unblocks faithful MG12 and the MG6C/D schedules. Design it accordingly.

- Files: `libs/shared/src/lib/form-template.types.ts` and `form-templates.ts`; renderer in
  `apps/web/src/app/shared/dynamic-form/`; pure logic in `libs/shared/src/lib/schedule.ts`.
- **Designation independence:** no behaviour may branch on the form code — the MG6 designation is
  disputed (`docs/answers/LER-1205-designation-mismatches.md`) and this build must not wait for it.
- **Additive only:** never rename or delete an existing field id; run `npm run orphan-scan` around any
  id change.
- After changing `libs/shared`, **restart the API** — the nest watcher does not pick up shared-lib
  rebuilds and will serve stale templates.
- Full mechanism and business rules: `docs/usecases/uc-04/prd.md` (§4 and §8).
