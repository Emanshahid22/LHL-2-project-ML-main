# LER-1091 — Sparse schedule threshold

_UC-04 MG6 Unused Material Schedule · epic: `docs/usecases/uc-04/epic.md` · PRD: `docs/usecases/uc-04/prd.md`_

## User Story
As a defence solicitor, I want a Complex case with fewer than five unused-material items flagged, so that the threshold matches the standard the scope sets.

## Acceptance Criteria
- Given a case marked Complex with 4 items, when the check evaluates, then the schedule is flagged sparse — the scope's DoD: "Completeness check fires correctly for 'Complex' cases with fewer than 5 items".
- Given a case marked Complex with exactly 5 items, when the check evaluates, then it is NOT flagged (the boundary is "fewer than 5").
- Given thresholds are needed, when they are defined, then they live in one place (`libs/shared/src/lib/completeness.ts` as `COMPLEXITY_THRESHOLDS`) and are **configurable, not hardcoded at call sites**.
- Given the pure helper `checkCompleteness({ itemCount, complexity })`, when it is called, then it returns `{ sparse, threshold, complexity }` and is unit-tested at every band boundary.
