# LER-1089 — Route sensitive items to UC-07

_UC-04 MG6 Unused Material Schedule · epic: `docs/usecases/uc-04/epic.md` · PRD: `docs/usecases/uc-04/prd.md`_

## User Story
As a disclosure officer, I want marking an item sensitive to trigger sensitive-material handling automatically, so that a sensitive item can never sit unmarked on a non-sensitive schedule through an omission.

## Acceptance Criteria
- Given any row's `classification` is set to Sensitive, when the change is made, then `hasSensitiveMaterial: true` is written into the draft values **with no further user action** — satisfying the scope's DoD line verbatim.
- Given the last sensitive row is removed or reclassified, when the change is made, then `hasSensitiveMaterial` is cleared — the flag must not latch on.
- Given `hasSensitiveMaterial` is derived, when the form renders, then it is never user-editable and never presented as an input.
- Given the flag is persisted, when the draft is reloaded, then the flag matches the rows (it is recomputed, not trusted from storage).
- Given the flag exists, when the draft is saved, then `DRAFT_SAVED` audit metadata records `hasSensitiveMaterial` alongside the item count.
- Given `orphan-scan` reports keys outside the template, when it runs, then `hasSensitiveMaterial` is recognised as a deliberate derived key and is NOT reported as an orphan.

## Notes & Constraints
- UC-07 does not exist yet, so the flag has no consumer. That is intended — the contract is the flag.
- **Sensitive means marked, not protected.** Do not describe this story, in code or UI copy, as making disclosure safe. Do not use red for the sensitivity indicator: red is reserved for UC-07.

- Files: `libs/shared/src/lib/form-template.types.ts` and `form-templates.ts`; renderer in
  `apps/web/src/app/shared/dynamic-form/`; pure logic in `libs/shared/src/lib/schedule.ts`.
- **Designation independence:** no behaviour may branch on the form code — the MG6 designation is
  disputed (`docs/answers/LER-1205-designation-mismatches.md`) and this build must not wait for it.
- **Additive only:** never rename or delete an existing field id; run `npm run orphan-scan` around any
  id change.
- After changing `libs/shared`, **restart the API** — the nest watcher does not pick up shared-lib
  rebuilds and will serve stale templates.
- Full mechanism and business rules: `docs/usecases/uc-04/prd.md` (§4 and §8).
