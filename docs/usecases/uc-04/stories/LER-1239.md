# LER-1239 — MG6 field-set rebuild from sourced research

_DevOps Bot ticket **LER-1239** (Story) · loaded 20 Aug 2026._

_UC-04 MG6 Unused Material Schedule · epic: `docs/usecases/uc-04/epic.md` · PRD: `docs/usecases/uc-04/prd.md`_

## User Story
As a defence solicitor completing an MG6, I want the form to carry the boxes that are actually printed on it, so that I am not filling in a nine-box approximation of a three-page official document.

## Acceptance Criteria
- Given the research corpus (`docs/mg-form-research-findings.md` § MG6, corroborated by two independent specimens), when MG6 ships, then every one of the 41 documented printed boxes exists on the template.
- Given the pre-existing MG6 field set, when the rebuild lands, then **every existing field id is unchanged** — including the UC-04 `unusedMaterialItems` schedule, its four columns and its `sensitivityFlag` / `complexityFieldId` wiring — and `npm run orphan-scan` reports zero orphans before and after.
- Given each added field, when it is inspected, then it carries a `provenance` **and** a `source` naming the printed box it came from and the specimen that corroborates it.
- Given a box whose control type is inferred rather than printed (the section 4-8 questions have blank answer spaces, not dropdowns), when it ships, then its provenance is `likely` and its source says the Yes/No typing is this project's inference.
- Given MG6, when it ships, then `verification` stays `'unverified'` and `templateVersion` is bumped, because a rebuilt field set is not a practitioner-verified one.
- Given `npm run conformance`, when it runs, then MG6 passes on both the structural and the sourcing tier.
- Given the suite, when it runs, then every pre-existing check stays green — the UC-04 schedule checks in particular.

## Notes & Constraints

- **No box that cannot be cited.** The research documents 41; anything beyond that is not added, and anything
  uncertain is recorded in `docs/usecases/uc-04/open-questions.md` rather than guessed.
- The three boxes the repo already had under different names (`underminesCase`, `underminesDetail`,
  `dateCompleted`) are cited in place rather than duplicated — two boxes asking the same question would be
  worse than one uncited box.
- `mapsTo` is added only where the case datum genuinely IS the field: the MG6 header URN and the "R v"
  defendant name. Nothing else.
- Target dates must NOT carry `noFutureDate`: a target date is a future date by definition.
- This is MG6's **field set**. UC-04 delivered the schedule *mechanics*; they are separate pieces of work,
  which is why this story exists at all — the LER-1031..1039 template block never covered MG6.
- Additive only; run `npm run orphan-scan` around any id change; restart the API after `libs/shared` changes.

## Definition of Done
- Delivered against the acceptance criteria above
- `npm run test:e2e` green and both builds pass
- `npm run conformance` and `npm run orphan-scan` pass
- Every existing `data-testid` intact
- Test drafts cleaned from `apps/api/prisma/dev.db`
