# LER-1082 — Row fields

_UC-04 MG6 Unused Material Schedule · epic: `docs/usecases/uc-04/epic.md` · PRD: `docs/usecases/uc-04/prd.md`_

## User Story
As a defence solicitor, I want each schedule row to carry a reference, description, material type and sensitivity classification, so that the schedule records what the item is and how it must be handled.

## Acceptance Criteria
- Given a schedule row, when it renders, then it has columns `itemReference`, `description`, `materialType` (select) and `classification` (select).
- Given the classification column, when it renders, then its options are exactly Non-Sensitive and Sensitive — the scope's two values, no third state.
- Given the material type column, when it renders, then it offers at least document, CCTV and forensic (the scope's examples) and the option list is data in the template, not hardcoded in the component.
- Given two rows claim the same `itemReference`, when the second is entered, then that row shows a duplicate-reference error and the other row is not invalidated.
- Given a duplicate reference exists, when autosave fires, then the draft still saves — drafts are allowed to be incomplete.
- Given a row column is required, when it is empty, then the row reads incomplete and an empty schedule does not count as complete (`isFieldValueComplete([])` must not return true).

## Notes & Constraints
- `isFieldValueComplete` currently returns true for any non-null value, so an empty array would count as complete today. Fix deliberately and test it.

- Files: `libs/shared/src/lib/form-template.types.ts` and `form-templates.ts`; renderer in
  `apps/web/src/app/shared/dynamic-form/`; pure logic in `libs/shared/src/lib/schedule.ts`.
- **Designation independence:** no behaviour may branch on the form code — the MG6 designation is
  disputed (`docs/answers/LER-1205-designation-mismatches.md`) and this build must not wait for it.
- **Additive only:** never rename or delete an existing field id; run `npm run orphan-scan` around any
  id change.
- After changing `libs/shared`, **restart the API** — the nest watcher does not pick up shared-lib
  rebuilds and will serve stale templates.
- Full mechanism and business rules: `docs/usecases/uc-04/prd.md` (§4 and §8).
