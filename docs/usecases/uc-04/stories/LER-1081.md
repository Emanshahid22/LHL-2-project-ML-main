# LER-1081 — Add Item action

_UC-04 MG6 Unused Material Schedule · epic: `docs/usecases/uc-04/epic.md` · PRD: `docs/usecases/uc-04/prd.md`_

## User Story
As a defence solicitor building a schedule, I want an "Add Item" action, so that I can create the next unused-material row without leaving the form.

## Acceptance Criteria
- Given a template declaring a group field, when the form renders, then a row table appears with an `Add Item` control carrying `data-testid="add-item"`.
- Given an empty schedule, when I press `Add Item`, then exactly one empty row is appended and focus moves into its first column.
- Given a schedule with rows, when I press `Add Item`, then the new row is appended at the end and existing rows are untouched.
- Given a new row is created, when it is appended, then it receives a `__id` set to a random uuid.
- Given rows are added, when autosave fires (existing 1.5s debounce), then the array persists under the group field id in `valuesJson` and reloading the draft restores every row.

## Notes & Constraints
- The renderer builds a `FormArray` of `FormGroup`s for a group field instead of a single `FormControl`.

- Files: `libs/shared/src/lib/form-template.types.ts` and `form-templates.ts`; renderer in
  `apps/web/src/app/shared/dynamic-form/`; pure logic in `libs/shared/src/lib/schedule.ts`.
- **Designation independence:** no behaviour may branch on the form code — the MG6 designation is
  disputed (`docs/answers/LER-1205-designation-mismatches.md`) and this build must not wait for it.
- **Additive only:** never rename or delete an existing field id; run `npm run orphan-scan` around any
  id change.
- After changing `libs/shared`, **restart the API** — the nest watcher does not pick up shared-lib
  rebuilds and will serve stale templates.
- Full mechanism and business rules: `docs/usecases/uc-04/prd.md` (§4 and §8).

## Definition of Done
- Delivered against the acceptance criteria above
- `npm run test:e2e` green and both builds pass
- `npm run conformance` and `npm run orphan-scan` pass
- Every existing `data-testid` intact
- Test drafts cleaned from `apps/api/prisma/dev.db`
