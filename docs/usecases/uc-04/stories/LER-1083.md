# LER-1083 — Stable item identity

_UC-04 MG6 Unused Material Schedule · epic: `docs/usecases/uc-04/epic.md` · PRD: `docs/usecases/uc-04/prd.md`_

## User Story
As a disclosure officer, I want each schedule item to keep a permanent identity separate from its number, so that audit records and sensitivity decisions stay attached to the right material when the schedule is renumbered.

## Acceptance Criteria
- Given a row is created, when it is appended, then it carries `__id` = a random uuid, and that value never changes for the life of the row.
- Given a row is edited, when any column value changes, then `__id` is unchanged.
- Given rows are reordered, when the order changes, then every `__id` is unchanged and no row is recreated.
- Given a row is deleted, when the remaining rows renumber, then their `__id`s are unchanged.
- Given identifiers reach audit rows and later storage keys, when `__id` is generated, then it contains no PII — it is never derived from a name, reference, description or file path.
- Given a draft is saved and reloaded, when the rows are restored, then each row's `__id` round-trips exactly.

## Notes & Constraints
- This is the story that prevents the defect the whole UC exists to avoid: identity must not be the number.

- Files: `libs/shared/src/lib/form-template.types.ts` and `form-templates.ts`; renderer in
  `apps/web/src/app/shared/dynamic-form/`; pure logic in `libs/shared/src/lib/schedule.ts`.
- **Designation independence:** no behaviour may branch on the form code — the MG6 designation is
  disputed (`docs/answers/LER-1205-designation-mismatches.md`) and this build must not wait for it.
- **Additive only:** never rename or delete an existing field id; run `npm run orphan-scan` around any
  id change.
- After changing `libs/shared`, **restart the API** — the nest watcher does not pick up shared-lib
  rebuilds and will serve stale templates.
- Full mechanism and business rules: `docs/usecases/uc-04/prd.md` (§4 and §8).
