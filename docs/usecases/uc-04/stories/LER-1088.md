# LER-1088 — Renumber on edit and reorder

_UC-04 MG6 Unused Material Schedule · epic: `docs/usecases/uc-04/epic.md` · PRD: `docs/usecases/uc-04/prd.md`_

## User Story
As a defence solicitor, I want editing or reordering items never to orphan a reference, so that every row still describes the material it started with.

## Acceptance Criteria
- Given a row is edited, when any column changes, then no other row is affected and no `__id` changes.
- Given rows are reordered, when the new order renders, then ordinals recompute to 1..n and every `__id` is preserved.
- Given reorder is offered, when it is implemented, then it moves the row within the array — it is NOT implemented as delete-and-re-add, which would destroy `__id` and its history.
- Given the scope's DoD requires numbering correct "across add, edit, and delete operations", when the suite runs, then edit and reorder are covered as their own paths, not inferred from the delete test.

## Notes & Constraints
- This is the third of the three required mutation paths; the QA story (LER-1093) asserts all three together.

- Files: `libs/shared/src/lib/form-template.types.ts` and `form-templates.ts`; renderer in
  `apps/web/src/app/shared/dynamic-form/`; pure logic in `libs/shared/src/lib/schedule.ts`.
- **Designation independence:** no behaviour may branch on the form code — the MG6 designation is
  disputed (`docs/answers/LER-1205-designation-mismatches.md`) and this build must not wait for it.
- **Additive only:** never rename or delete an existing field id; run `npm run orphan-scan` around any
  id change.
- After changing `libs/shared`, **restart the API** — the nest watcher does not pick up shared-lib
  rebuilds and will serve stale templates.
- Full mechanism and business rules: `docs/usecases/uc-04/prd.md` (§4 and §8).

## Definition of Done
- Delivered against the acceptance criteria above
- `npm run test:e2e` green and both builds pass
- `npm run conformance` and `npm run orphan-scan` pass
- Every existing `data-testid` intact
- Test drafts cleaned from `apps/api/prisma/dev.db`
