# LER-1090 — Completeness check

_UC-04 MG6 Unused Material Schedule · epic: `docs/usecases/uc-04/epic.md` · PRD: `docs/usecases/uc-04/prd.md`_

## User Story
As a defence solicitor, I want to be warned when my schedule looks implausibly sparse for the case, so that I notice unused material I have forgotten to schedule.

## Acceptance Criteria
- Given a schedule reaches 10 items, when the count is met, then the completeness check evaluates (the scope: "fires after 10+ items").
- Given a finalisation attempt occurs, when it is made, then the check evaluates regardless of item count. (No finalise endpoint exists yet — expose the hook and test it directly.)
- Given the check evaluates, when it completes, then the outcome is written to the audit log as `COMPLETENESS_CHECKED`, **whether or not it flagged** — a check that only logs failures cannot prove it ran.
- Given the check flags a sparse schedule, when the advisory appears, then it is non-blocking: saving, navigating and completing all still work.
- Given no complexity has been chosen, when the check would evaluate, then it does not fire and records `complexity: 'unknown'` rather than guessing a band.
- Given `AuditAction` today is `FORM_INITIATED | DRAFT_SAVED | AUTO_POPULATED`, when the action is added, then the union gains `COMPLETENESS_CHECKED` and an audit failure still never breaks a user action.

## Notes & Constraints
- Case complexity is a manual field with a documented migration path to case-derived — see PRD §6 for the decision and its justification.

- Files: `libs/shared/src/lib/form-template.types.ts` and `form-templates.ts`; renderer in
  `apps/web/src/app/shared/dynamic-form/`; pure logic in `libs/shared/src/lib/schedule.ts`.
- **Designation independence:** no behaviour may branch on the form code — the MG6 designation is
  disputed (`docs/answers/LER-1205-designation-mismatches.md`) and this build must not wait for it.
- **Additive only:** never rename or delete an existing field id; run `npm run orphan-scan` around any
  id change.
- After changing `libs/shared`, **restart the API** — the nest watcher does not pick up shared-lib
  rebuilds and will serve stale templates.
- Full mechanism and business rules: `docs/usecases/uc-04/prd.md` (§4 and §8).
