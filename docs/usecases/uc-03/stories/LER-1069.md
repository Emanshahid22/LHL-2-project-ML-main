## User Story
As a defence solicitor, I want the declaration wording cryptographically pinned, so that a change to it cannot pass unnoticed through a merge or a careless edit.

## Acceptance Criteria
- Given the shipped declaration, when it is hashed, then the digest equals the pinned `MG11_DECLARATION_SHA256`.
  - Covered by: e2e/uc03-mg11-wizard.spec.ts › `the shipped declaration matches its integrity hash`
- Given a wording change, when it is made, then the constant and its hash must change in the same commit or the system will not run.
  - Covered by: e2e/uc03-mg11-wizard.spec.ts › `the API refuses to start on a tampered declaration`

## Notes & Constraints

- The test hashes the wording itself and compares with the constant, so the pin is verified independently
  of the API's own check — a single shared helper could otherwise be wrong in both places identically.
- The regeneration command is recorded in a comment beside the constant, because the friction is intended to
  be deliberate rather than mysterious.

- The wizard is a **shell around** `DynamicForm`, never a fork: `apps/web/.../form-fill/mg11-wizard/`
  passes `visibleFieldIds` and the renderer still owns the single `FormGroup`.
- Shared, pure: `libs/shared/src/lib/mg11-declaration.ts`, `narrative-flags.ts`, `mg11-witness.ts`.
- MG11 carries **no `verification` marker**, which means "not yet assessed" — it is the quality bar but is
  **not** practitioner-verified. Do not mark it verified because it looks good (CLAUDE.md rule 2).
- **Additive only:** a field id is permanent; `valuesJson` is keyed by id.
