## User Story
As a witness, I want the declaration I am signing shown to me exactly as it stands, so that what I am told I am signing is what I am actually signing.

## Acceptance Criteria
- Given step 3, when it renders, then the statutory declaration appears as read-only text in its own block.
  - Covered by: e2e/uc03-mg11-wizard.spec.ts › `the declaration is read-only text, not an editable field`
- Given step 3, when I inspect the declaration, then it is not an editable form field and there is no input holding the wording.
  - Covered by: e2e/uc03-mg11-wizard.spec.ts › `the declaration is read-only text, not an editable field`
- Given any form, when a client tries to save a `declarationText` value, then the API refuses it with 422.
  - Covered by: e2e/uc03-mg11-wizard.spec.ts › `the API rejects declaration tampering`

## Notes & Constraints

- **A bug found by verification, not review:** the declaration originally rendered twice, because the
  checkbox's own label was the wording. The wording now appears once, in the read-only block, and the
  checkbox says only that it is confirmed.
- The wording is imported from `@mgs/shared` by the client. It is **not** in the template payload, so it
  never travels as data.

- The wizard is a **shell around** `DynamicForm`, never a fork: `apps/web/.../form-fill/mg11-wizard/`
  passes `visibleFieldIds` and the renderer still owns the single `FormGroup`.
- Shared, pure: `libs/shared/src/lib/mg11-declaration.ts`, `narrative-flags.ts`, `mg11-witness.ts`.
- MG11 carries **no `verification` marker**, which means "not yet assessed" — it is the quality bar but is
  **not** practitioner-verified. Do not mark it verified because it looks good (CLAUDE.md rule 2).
- **Additive only:** a field id is permanent; `valuesJson` is keyed by id.
