## User Story
As a defence solicitor, I need certainty that the declaration wording cannot be edited through the product, so that no witness ever signs something other than the statutory declaration.

## Acceptance Criteria
- Given the whole system, when the declaration is needed, then it comes from a single exported constant and there is no second copy anywhere.
  - Covered by: e2e/uc03-mg11-wizard.spec.ts › `the shipped declaration matches its integrity hash`
- Given a draft, when it is saved, then it records only the confirmation boolean and never the wording.
  - Covered by: e2e/uc03-mg11-wizard.spec.ts › `the declaration is read-only text, not an editable field`
- Given any form — not just MG11 — when a client includes a `declarationText` key, then the API refuses the save with 422.
  - Covered by: e2e/uc03-mg11-wizard.spec.ts › `the API rejects declaration tampering`

## Notes & Constraints

- `FORBIDDEN_DRAFT_VALUE_KEYS = ['declarationText']` is checked on **every** save path, on every form, so
  no other form can be used as a route to smuggle wording into `valuesJson`.
- The wording is not in the `GET /form-templates/MG11` payload. The client imports it from `@mgs/shared`,
  so there is no request in which it could be substituted.

- The wizard is a **shell around** `DynamicForm`, never a fork: `apps/web/.../form-fill/mg11-wizard/`
  passes `visibleFieldIds` and the renderer still owns the single `FormGroup`.
- Shared, pure: `libs/shared/src/lib/mg11-declaration.ts`, `narrative-flags.ts`, `mg11-witness.ts`.
- MG11 carries **no `verification` marker**, which means "not yet assessed" — it is the quality bar but is
  **not** practitioner-verified. Do not mark it verified because it looks good (CLAUDE.md rule 2).
- **Additive only:** a field id is permanent; `valuesJson` is keyed by id.
