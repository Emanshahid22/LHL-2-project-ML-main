## User Story
As a defence solicitor, I want the witness's confirmation of the declaration recorded as a discrete act, so that the file shows the declaration was put to them.

## Acceptance Criteria
- Given step 3, when it renders, then a confirmation checkbox sits with the declaration.
  - Covered by: e2e/uc03-mg11-wizard.spec.ts › `cannot advance past the declaration until it is confirmed`
- Given I tick it, when the draft saves, then the draft records `declarationConfirmed: true` and no wording.
  - Covered by: e2e/uc03-mg11-wizard.spec.ts › `autosave works from every step`
- Given a client sends a non-boolean confirmation on MG11, when the save is attempted, then the API refuses it with 422 — a truthy string is not a tick.
  - Covered by: e2e/uc03-mg11-wizard.spec.ts › `the API rejects declaration tampering`

## Notes & Constraints

- `declarationConfirmed` is a required checkbox, so it uses `Validators.requiredTrue` — an unticked box is
  not merely empty, it is invalid.
- Checkboxes sit outside `mat-form-field`, which is why they carry their own required marker while text
  fields rely on Material's.

- The wizard is a **shell around** `DynamicForm`, never a fork: `apps/web/.../form-fill/mg11-wizard/`
  passes `visibleFieldIds` and the renderer still owns the single `FormGroup`.
- Shared, pure: `libs/shared/src/lib/mg11-declaration.ts`, `narrative-flags.ts`, `mg11-witness.ts`.
- MG11 carries **no `verification` marker**, which means "not yet assessed" — it is the quality bar but is
  **not** practitioner-verified. Do not mark it verified because it looks good (CLAUDE.md rule 2).
- **Additive only:** a field id is permanent; `valuesJson` is keyed by id.
