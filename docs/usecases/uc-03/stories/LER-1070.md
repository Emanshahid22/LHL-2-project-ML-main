## User Story
As a defence solicitor, I want the system to refuse to run rather than serve an unverified declaration, so that a drifted wording fails loudly instead of reaching a witness.

## Acceptance Criteria
- Given a declaration that does not match its hash, when the API starts, then it exits non-zero before serving any request, with a message naming an integrity check failure.
  - Covered by: e2e/uc03-mg11-wizard.spec.ts › `the API refuses to start on a tampered declaration`
- Given a matching declaration, when the API starts, then it boots normally.
  - Covered by: e2e/uc03-mg11-wizard.spec.ts › `the shipped declaration matches its integrity hash`

## Notes & Constraints

- `assertDeclarationIntegrity()` is called in `main.ts` **before** `NestFactory.create`, so there is no
  window in which the app is listening with an unverified declaration. There is **no degraded mode**:
  serving with an unknown declaration would be worse than not serving.
- The test spawns a Node process with a tampered constant and asserts the non-zero exit — the only honest way
  to test a fatal boot check.
- Side benefit used daily: the startup log line confirms a fresh boot, which is how you tell whether the API
  has picked up a `libs/shared` rebuild.

- The wizard is a **shell around** `DynamicForm`, never a fork: `apps/web/.../form-fill/mg11-wizard/`
  passes `visibleFieldIds` and the renderer still owns the single `FormGroup`.
- Shared, pure: `libs/shared/src/lib/mg11-declaration.ts`, `narrative-flags.ts`, `mg11-witness.ts`.
- MG11 carries **no `verification` marker**, which means "not yet assessed" — it is the quality bar but is
  **not** practitioner-verified. Do not mark it verified because it looks good (CLAUDE.md rule 2).
- **Additive only:** a field id is permanent; `valuesJson` is keyed by id.
