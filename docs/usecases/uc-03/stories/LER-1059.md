## User Story
As a defence solicitor, I want a generous text area for the witness's account, so that the statement can be recorded in their own words without fighting the form.

## Acceptance Criteria
- Given step 2, when it renders, then the narrative has its own dedicated field with a large text area.
  - Covered by: e2e/uc03-mg11-wizard.spec.ts › `a live word count tracks the narrative, and spell-check is on`
- Given text in the narrative, when flags are present, then the highlight layer lines up with the text it underlines.
  - Covered by: e2e/uc03-mg11-wizard.spec.ts › `marks align with the text they underline`
- Given step 2, when I type and stop, then the narrative autosaves like any other field.
  - Covered by: e2e/uc03-mg11-wizard.spec.ts › `autosave works from every step`

## Notes & Constraints

- `statementText` is rendered by a dedicated `NarrativeField` component rather than the generic textarea
  branch, because it needs a highlight layer, a word count and a flag summary. It is still driven by the
  same `FormControl` from the shared `FormGroup`.
- **A bug found by verification, not review:** the highlight backdrop originally sat *below* the textarea,
  which killed tooltips. It now layers *above*, transparent, `pointer-events: none` except on marks, with
  mousedown forwarding the caret.

- The wizard is a **shell around** `DynamicForm`, never a fork: `apps/web/.../form-fill/mg11-wizard/`
  passes `visibleFieldIds` and the renderer still owns the single `FormGroup`.
- Shared, pure: `libs/shared/src/lib/mg11-declaration.ts`, `narrative-flags.ts`, `mg11-witness.ts`.
- MG11 carries **no `verification` marker**, which means "not yet assessed" — it is the quality bar but is
  **not** practitioner-verified. Do not mark it verified because it looks good (CLAUDE.md rule 2).
- **Additive only:** a field id is permanent; `valuesJson` is keyed by id.
