THE MOST IMPORTANT RULE ON THIS TICKET — never invent a statutory format
- A criminal case file carries references (URN, ASN, custody number, collar number, CPS reference) whose
  exact character formats this project has NOT sourced. The research evidences that the BOXES exist. It
  does not state their formats.
- A rule that rejects a valid URN is worse than no rule: it teaches a solicitor to work around the product
  on a document that goes to court.
- Therefore: a format may be `error` severity ONLY if its provenance is 'documented' AND it carries a real
  source citation. Everything else is 'advisory' — it hints, it never invalidates a control, it never
  blocks a save.
- Enforce this TWICE: in `severityFor()` at runtime (so editing a template cannot bypass it) and in
  `npm run conformance` (so the mistake fails CI). Both, not either.
- If you find yourself writing a regex you cannot cite, stop and put the question in
  docs/usecases/uc-05/open-questions.md instead.

Shared-Library Rules
- Reuse the existing type system — do NOT invent a parallel one. A cross-field rule is declared on the
  FIELD that owns it, so nothing keys off a form code (the same discipline UC-04 used for the schedule).
- Keep validation.ts PURE and framework-free: both apps and the tests share one definition of validity.
- Formats live in the registry, never as raw regexes in templates. Seven templates carry a URN box; a bad
  pattern copied seven times is seven edits and six chances to miss one.
- ADDITIVE ONLY: never rename or delete an existing field id — values are already stored under those ids
  in FormDraft.valuesJson and renaming strands them on the next autosave (1.5s after a keystroke).
  Run `npm run orphan-scan` before and after any id change.
- After changing libs/shared you MUST restart the API: the nest watcher does not pick up libs/shared
  rebuilds, so `npm run dev` needs restarting or the API serves stale templates. The startup log line from
  the MG11 declaration integrity check confirms a fresh boot.

Backend Rules
- Reuse existing modules/controllers/services/DTOs/guards/Prisma models — don't duplicate.
- NO schema migration is needed or wanted. Findings are COMPUTED, never stored — a stored finding goes
  stale the moment a rule is corrected, and these rules will change as formats get sourced.
- The API rejects what it cannot safely STORE (type shape, 422) and records what is merely WRONG
  (semantics, audit counts). Do NOT reject a draft save for a semantic rule: a form is invalid for most of
  the time a human is filling it in, and rejecting would break autosave.
- Audit metadata carries COUNTS ONLY — never a field value, never a failing string.
- Audit writes must never break a user action (existing AuditService behaviour).
- The finalisation gate is what validateForm exists for and is UNREACHABLE until a finalise action exists
  (UC-10). Write the hook, document it, do not invent an endpoint for it.

Frontend Rules
- Reuse the shared DynamicForm renderer. Do NOT special-case forms in components; if the renderer lacks
  something, extend the renderer (the MG11 wizard is a shell AROUND it, not a fork).
- Angular validators must be DERIVED from the shared rule definitions, not written twice. Only
  error-severity rules become validators; advisory rules must never invalidate a control.
- Cross-field findings go in the Consistency Issues panel below the form section, NOT in any field's inline
  error slot. The scope is explicit about this.
- Preserve every existing data-testid; the E2E suite depends on them. Add new ones for validation
  (consistency-issues, validation-hint, format-hint).
- Handle loading/empty/error states; keep AA contrast and visible focus (public-sector context).
- Design tokens only: apps/web/src/styles/_tokens.scss. Do not hardcode colour. Amber is advisory; errors
  use Material's existing error token; RED IS RESERVED FOR UC-07 SENSITIVE MATERIAL — do not introduce a
  third red in this UC.
- The panel needs role="status" so findings are announced without stealing focus.

Correctness Rules specific to this UC — read twice
- Provenance decides severity. A template asking for more severity than its format's provenance permits is
  overridden at runtime AND fails conformance.
- A cross-field rule fires only when BOTH operands have values.
- An `ambiguous` case datum SUPPRESSES the rule and says why. Never pick one of two offence dates to
  compare against — that produces a confident wrong answer, which is worse than silence.
- Severity belongs to the RULE, not the field or the form. On MG11's statementDate: earlier than the
  witness's date of birth is an ERROR (impossible); later than the case hearing date is ADVISORY (a further
  statement after the first hearing is ordinary practice).
- Do NOT put a collar-number pattern on the composite officer boxes (MG1/MG3/MG4 officerInCase,
  MG5/MG16 officerCompleting). Each holds a name, a rank AND a number in one free-text box; a pattern over
  it would reject correct input. Assert that no such rule exists, so a later well-meaning addition fails.
- Do NOT add a field so a rule has somewhere to live. Two of the scope's four named formats have no field
  (CPS reference, collar number). That is a finding to record, not a gap to fill with an invented box.
- A form with no findings is NOT a verified form. Most templates are `unverified`; the panel must say so.
- Do NOT switch to provideNativeDateAdapter — Date objects in controls break UC-02's provenance matching
  and would remove every auto-fill badge.

Full-Stack Coordination
- libs/shared IS the contract: the API's DTOs and the client's types are the same exported
  definitions, so a shape change is one edit reviewed once — never two hand-kept copies.
- After ANY libs/shared change: rebuild it, restart the API, and curl a template to verify the
  served field count — tsc emits on type errors and the nest watcher serves stale dists silently
  (HANDOVER §5).
- Frontend and backend for a use case land together on the UC branch as one PR; a UI that ships
  ahead of its endpoint (or the reverse) is half a feature and reviews as one.

Third-Party Integrations
