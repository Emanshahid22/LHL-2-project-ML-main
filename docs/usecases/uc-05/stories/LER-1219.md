# LER-1219 — Conditional requirement

_UC-05 Field Validation · epic: `docs/usecases/uc-05/epic.md` · PRD: `docs/usecases/uc-05/prd.md`_

_DevOps Bot ticket **LER-1219** (Story, To Do) · build stage order: story 13 of 16._

## User Story
As a defence solicitor, I want a follow-up box to become required when my answer calls for it, so that answering "yes" to the disclosure test cannot be left unexplained.

## Acceptance Criteria
- Given MG6 with `underminesCase` unanswered or `no`, when the form renders, then `underminesDetail` is optional and is not counted as an outstanding required field.
- Given MG6 with `underminesCase` set to `yes`, when it is set, then `underminesDetail` becomes required from that moment, with an **error**-severity finding while it is empty.
- Given that state, when I change `underminesCase` back to `no`, then the requirement lifts and its message clears.
- Given the required-field progress counter, when a conditional requirement becomes active, then the denominator reflects it, so progress does not read as complete while a required answer is missing.
- Given a `requiredWhen` rule pointing at a field that does not exist, when `npm run conformance` runs, then it fails.

## Notes & Constraints

- `requiredWhen: { fieldId: 'underminesCase', equals: 'yes' }` is declared on `underminesDetail`, so the
  rule sits with the field it constrains and no code branches on the form code.
- This interacts with the progress counter, which is shared with the MG11 wizard's per-step count — check
  both. `requiredFieldIds` is currently static per template; a conditional requirement makes it a function
  of the current values.
- The MG6 pair is the case the disclosure schedule was built to support (UC-04 PRD §8), which is why it is
  the worked example.

- Rule engine: `libs/shared/src/lib/validation.ts` (new, pure). Types:
  `libs/shared/src/lib/form-template.types.ts`. Rules on fields: `form-templates.ts`.
- **No invented format.** A format may be `error` severity only if its provenance is `documented` with a
  cited source. Everything else is advisory. This is enforced by `severityFor()` and by
  `npm run conformance` — not by good intentions.
- **Additive only:** never rename or delete a field id; bump `templateVersion` on any template whose rules
  change; run `npm run orphan-scan` around any id change.
- Reuse the shared renderer. Do not special-case a form code; a rule is declared on the field that owns it.
- After changing `libs/shared`, **restart the API** — the nest watcher does not pick up shared-lib rebuilds.
- Full mechanism and business rules: `docs/usecases/uc-05/prd.md` (§4 and §8).
