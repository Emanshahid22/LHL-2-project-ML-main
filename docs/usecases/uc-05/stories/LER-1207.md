# LER-1207 — Named format registry with provenance

_UC-05 Field Validation · epic: `docs/usecases/uc-05/epic.md` · PRD: `docs/usecases/uc-05/prd.md`_

_DevOps Bot ticket **LER-1207** (Story, To Do) · build stage order: story 01 of 16._

## User Story
As a defence solicitor, I want every format rule to state where it came from, so that the product can tell me a reference looks wrong without pretending to certainty it does not have.

## Acceptance Criteria
- Given the shared library, when a format is defined, then it lives in `FIELD_FORMATS` carrying a pattern, a user-facing hint, an example, a `provenance` and an optional `source` citation.
- Given a template field, when it needs a format rule, then it names the format (`validation: { format: 'urn' }`) rather than carrying a raw regex and a hand-written message.
- Given a template naming a format that is not in the registry, when `npm run conformance` runs, then it fails with the field named.
- Given a format whose provenance is `documented`, when it carries no `source`, then conformance fails — a documented claim without a citation is not documented.
- Given the three existing telephone `pattern` rules, when the registry lands, then they are expressed through it with no change in behaviour, so there is one definition of a telephone format rather than three.

## Notes & Constraints

- The registry is the reason a format can be corrected once rather than per field. Seven templates carry a
  URN box; a wrong URN pattern copied seven times is seven edits and six chances to miss one.
- `source` is free text but must be a real citation a reader can follow (document name and section), not
  "research".
- Do NOT add a format for anything the research does not evidence. See LER-1212 (URN and ASN formats, advisory pending sourcing).

- Rule engine: `libs/shared/src/lib/validation.ts` (new, pure). Types:
  `libs/shared/src/lib/form-template.types.ts`. Rules on fields: `form-templates.ts`.
- **No invented format.** A format may be `error` severity only if its provenance is `documented` with a
  cited source. Everything else is advisory. This is enforced by `severityFor()` and by
  `npm run conformance` — not by good intentions.
- **Additive only:** never rename or delete a field id; bump `templateVersion` on any template whose rules
  change; run `npm run orphan-scan` around any id change.
- Reuse the shared renderer. Do not special-case a form code; a rule is declared on the field that owns it.
- After changing `libs/shared`, **restart the API** — the nest watcher does not pick up shared-lib rebuilds.
- Full mechanism and business rules: `docs/usecases/uc-05/prd.md` (§4 and §8).
