# LER-1209 — Blur-time firing and automatic clearing

_UC-05 Field Validation · epic: `docs/usecases/uc-05/epic.md` · PRD: `docs/usecases/uc-05/prd.md`_

_DevOps Bot ticket **LER-1209** (Story, To Do) · build stage order: story 03 of 16._

## User Story
As a defence solicitor, I want an error to appear when I leave a field and disappear when I fix it, so that the form corrects me without nagging me mid-word.

## Acceptance Criteria
- Given a field I am typing into, when the value is momentarily invalid, then no error is shown while it still has focus.
- Given an invalid field, when I move focus away from it, then the error appears below the field.
- Given a shown error, when I correct the value to a valid one, then the error clears with no further action — no blur, no save, no reload.
- Given a shown advisory hint, when I correct the value, then the hint clears the same way.
- Given a cross-field finding in the Consistency Issues panel, when I correct either operand, then that finding leaves the panel.
- Given the scope's Definition of Done line "Validation errors clear automatically when the field is corrected to a valid value", when the suite runs, then a check proves it for a single-field error, an advisory hint and a cross-field finding.

## Notes & Constraints

- Display is already gated on `control.touched`, which Angular Material sets on blur, so the firing rule is
  delivered. This story asserts it against the scope's wording and extends it to the two new finding kinds.
- Clearing is inherent: messages are computed from control state on every change, not stored. The value of
  the story is the assertion, because "inherent" is how behaviour quietly regresses.

- Rule engine: `libs/shared/src/lib/validation.ts` (new, pure). Types:
  `libs/shared/src/lib/form-template.types.ts`. Rules on fields: `form-templates.ts`.
- **No invented format.** A format may be `error` severity only if its provenance is `documented` with a
  cited source. Everything else is advisory. This is enforced by `severityFor()` and by
  `npm run conformance` — not by good intentions.
- **Additive only:** never rename or delete a field id; bump `templateVersion` on any template whose rules
  change; run `npm run orphan-scan` around any id change.
- Reuse the shared renderer. Do not special-case a form code; a rule is declared on the field that owns it.
- After changing `libs/shared`, **restart the API** — the nest watcher does not pick up shared-lib rebuilds.
- Full mechanism and business rules: `docs/usecases/uc-05/prd.md` (§4 and §8).
