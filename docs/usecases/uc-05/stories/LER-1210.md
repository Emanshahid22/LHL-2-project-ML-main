# LER-1210 — Required-field validation across three form types

_UC-05 Field Validation · epic: `docs/usecases/uc-05/epic.md` · PRD: `docs/usecases/uc-05/prd.md`_

_DevOps Bot ticket **LER-1210** (Story, To Do) · build stage order: story 04 of 16._

## User Story
As a defence solicitor, I want every kind of empty required box to tell me it is required, so that an incomplete file is obvious before it leaves my desk rather than after.

## Acceptance Criteria
- Given a required text, textarea, date, select or checkbox field left empty, when I blur it, then the message "This field is required" appears below it.
- Given a required field with an error, when the form renders, then the field is visibly marked as being in error using the design system's error token.
- Given a required repeating group with no rows, when the group is touched, then it reads as incomplete rather than complete (the empty-array case UC-04 fixed).
- Given a required field made conditionally required by another field's value, when the trigger is set, then it validates as required from that moment.
- Given the scope's Definition of Done line "tested with a deliberately incomplete form across 3 different MG form types", when the suite runs, then it asserts this on **MG11**, **MG4** and **MG6** — chosen because between them they cover text, textarea, date, select, checkbox, a required group and a conditional requirement.

## Notes & Constraints

- The required-field message and marker are already delivered (`inline validation message appears for an
  empty required field`). What is new is coverage: the DoD asks for three form types and distinct field
  kinds, which no single existing check provides.
- The required marker is Material's own. Do not add a second asterisk inside a `mat-form-field` — that
  produced "URN * *" once already. Checkboxes sit outside the form field and do add their own.

- Rule engine: `libs/shared/src/lib/validation.ts` (new, pure). Types:
  `libs/shared/src/lib/form-template.types.ts`. Rules on fields: `form-templates.ts`.
- **No invented format.** A format may be `error` severity only if its provenance is `documented` with a
  cited source. Everything else is advisory. This is enforced by `severityFor()` and by
  `npm run conformance` — not by good intentions.
- **Additive only:** never rename or delete a field id; bump `templateVersion` on any template whose rules
  change; run `npm run orphan-scan` around any id change.
- Reuse the shared renderer. Do not special-case a form code; a rule is declared on the field that owns it.
- After changing `libs/shared`, **restart the API** — the nest watcher does not pick up shared-lib rebuilds.
- Full mechanism and business rules: `docs/usecases/uc-05/prd.md` (§4 and §8).
