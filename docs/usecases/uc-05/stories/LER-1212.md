# LER-1212 — URN and ASN formats, advisory pending sourcing

_UC-05 Field Validation · epic: `docs/usecases/uc-05/epic.md` · PRD: `docs/usecases/uc-05/prd.md`_

_DevOps Bot ticket **LER-1212** (Story, To Do) · build stage order: story 06 of 16._

## User Story
As a defence solicitor, I want a suspicious case reference queried rather than rejected, so that a genuine reference in a shape we have not catalogued still goes on the form.

## Acceptance Criteria
- Given the registry, when `urn`, `asn` and `custodyNumber` are defined, then each carries `provenance: 'inference'` and no `source`, because the research evidences that the **box** exists but never its character format.
- Given a URN field on any of the seven templates that carry one, when I enter a value that does not match the inferred shape, then an advisory hint appears and the control stays valid.
- Given that advisory, when I save the draft, then it saves — a badly formatted URN is recorded in the advisory count, not refused.
- Given the advisory hint, when I read it, then it says the format is unverified and shows the example shape, so I can tell "we are not sure" from "you are wrong".
- Given any attempt to mark these three formats `error` severity, when conformance runs, then it fails.

## Notes & Constraints

- Evidence position: `docs/mg-form-research-findings.md` records the URN and ASN **fields** as
  `documented` on MG3/MG4/MG12/MG15/MG16 — that is the box existing, not its format. No source in the
  corpus states the character format, so an `error`-severity pattern here would be invented.
- The patterns encode the shape of the *examples* seen (the MG1 placeholder `01AB0123456/24`), which is why
  provenance is `inference` and not even `likely`.
- Sourcing these formats is a practitioner question (`human-instructions.txt`). Answering it upgrades these
  three rules to errors — a one-line provenance change per format, plus a source. That upgrade path is the
  point of the design.

- Rule engine: `libs/shared/src/lib/validation.ts` (new, pure). Types:
  `libs/shared/src/lib/form-template.types.ts`. Rules on fields: `form-templates.ts`.
- **No invented format.** A format may be `error` severity only if its provenance is `documented` with a
  cited source. Everything else is advisory. This is enforced by `severityFor()` and by
  `npm run conformance` — not by good intentions.
- **Additive only:** never rename or delete a field id; bump `templateVersion` on any template whose rules
  change; run `npm run orphan-scan` around any id change.
- Reuse the shared renderer. Do not special-case a form code; a rule is declared on the field that owns it.
- After changing `libs/shared`, **restart the API** — the nest watcher does not pick up shared-lib rebuilds.
- Full mechanism and business rules: `docs/usecases/uc-05/prd.md` (§4 and §8).
