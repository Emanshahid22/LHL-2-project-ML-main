## User Story
As a delivery lead, I want one automated check per Definition of Done line, so that UC-05 is provably finished rather than asserted to be.

## Acceptance Criteria
- Given DoD line 1, when the suite runs, then required-field validation is asserted on a deliberately incomplete form across **three** MG form types (MG11, MG4, MG6), covering text, textarea, date, select, checkbox, a required group and a conditional requirement.
- Given DoD line 2, when the suite runs, then a check proves a DD/MM/YYYY format violation and an impossible date are both rejected, and that the format hint is shown.
- Given DoD line 3, when the suite runs, then the offence-date-after-charge-date check is asserted for valid ordering, reversed ordering, equal dates, ambiguous case data and a standalone draft.
- Given DoD line 4, when the suite runs, then automatic clearing is asserted for a single-field error, an advisory hint and a cross-field finding.
- Given the epic's own bar, when the suite runs, then checks prove that an advisory format does not block saving, that no composite officer field carries a format rule, and that no template references `cpsReference`.
- Given the guardrails, when `npm run conformance` and `npm run orphan-scan` run, then both pass, and conformance carries a planted-defect self-test for each new structural rule.
- Given the whole suite, when it runs, then every pre-existing check stays green and every `data-testid` is intact.

## Notes & Constraints

- Cite each check by spec file and test name in the PR, mapped to its DoD line — the format
  `docs/acceptance-mapping.md` uses.
- Clean up test data: snapshot draft ids before, log created ids via `E2E_DRAFT_LOG`, delete only the
  difference. The user's own drafts must survive.
- If a DoD line cannot be fully proven, record it as a coverage gap in `open-questions.md` rather than
  citing a check that does not cover it. UC-03's PDF-dependent criteria are the precedent.

- Rule engine: `libs/shared/src/lib/validation.ts` (new, pure). Types:
  `libs/shared/src/lib/form-template.types.ts`. Rules on fields: `form-templates.ts`.
- **No invented format.** A format may be `error` severity only if its provenance is `documented` with a
  cited source. Everything else is advisory. This is enforced by `severityFor()` and by
  `npm run conformance` — not by good intentions.
- **Additive only:** never rename or delete a field id; bump `templateVersion` on any template whose rules
  change; run `npm run orphan-scan` around any id change.
- Reuse the shared renderer. Do not special-case a form code; a rule is declared on the field that owns it.
- After changing `libs/shared`, **restart the API** — the nest watcher does not pick up shared-lib rebuilds.
- Full mechanism and business rules: `docs/usecases/uc-05/prd.md` (§4 and §8).

## Definition of Done
- Delivered against the acceptance criteria above
- `npm run test:e2e` green and both builds pass
- `npm run conformance` and `npm run orphan-scan` pass
- Every existing `data-testid` intact
- Test drafts cleaned from `apps/api/prisma/dev.db`
