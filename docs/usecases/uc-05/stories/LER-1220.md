# LER-1220 — Interview start and end ordering

_UC-05 Field Validation · epic: `docs/usecases/uc-05/epic.md` · PRD: `docs/usecases/uc-05/prd.md`_

_DevOps Bot ticket **LER-1220** (Story, To Do) · build stage order: story 14 of 16._

## User Story
As a defence solicitor, I want an interview that ends before it starts flagged, so that a transposed pair of times does not sit unnoticed in the record of a taped interview.

## Acceptance Criteria
- Given MG2 or MG15 with both `interviewStart` and `interviewEnd` set, when the end is earlier than the start, then an **error**-severity finding appears in the Consistency Issues panel.
- Given either field alone, when only one is set, then no finding appears.
- Given equal times, when both are set to the same value, then a finding appears — a zero-length interview is a data-entry error.
- Given a flagged finding, when I correct either time, then it clears automatically.
- Given the rule, when it is declared, then it is declared identically on both MG2 and MG15 through the same rule shape, with no code aware of either form code.

## Notes & Constraints

- This is the **only** cross-field pair that exists within a single template today, which makes it the
  cleanest test of the sibling-field path of the engine (the scope's two named pairs both need a case datum).
- The rule compares `time` values, not dates, and assumes a same-day interview — which both templates do,
  each carrying a single `interviewDate`. An interview crossing midnight would need a different rule; record
  it as an open question rather than guessing at one.
- **MG2's designation is disputed** (memo A2: officially the Special Measures Assessment, with interview
  content belonging on MG15). If A2 is answered, MG2's interview fields may move to MG15 — the rule moves
  with the fields, which is the point of declaring it on the field.

- Rule engine: `libs/shared/src/lib/validation.ts` (new, pure). Types:
  `libs/shared/src/lib/form-template.types.ts`. Rules on fields: `form-templates.ts`.
- **No invented format.** A format may be `error` severity only if its provenance is `documented` with a
  cited source. Everything else is advisory. This is enforced by `severityFor()` and by
  `npm run conformance` — not by good intentions.
- **Additive only:** never rename or delete a field id; bump `templateVersion` on any template whose rules
  change; run `npm run orphan-scan` around any id change.
- Reuse the shared renderer. Do not special-case a form code; a rule is declared on the field that owns it.
- After changing `libs/shared`, **restart the API** — the nest watcher does not pick up shared-lib rebuilds.
- Full mechanism and business rules: `docs/usecases/uc-05/prd.md` (§4 and §8).
