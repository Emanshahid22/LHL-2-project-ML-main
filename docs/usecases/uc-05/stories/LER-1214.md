# LER-1214 — CPS reference format with no field to attach it to

_UC-05 Field Validation · epic: `docs/usecases/uc-05/epic.md` · PRD: `docs/usecases/uc-05/prd.md`_

_DevOps Bot ticket **LER-1214** (Story, To Do) · build stage order: story 08 of 16._

## User Story
As a defence solicitor, I want the product to be honest that it cannot check a CPS reference yet, so that nobody assumes a check is running when no box exists to run it on.

## Acceptance Criteria
- Given the registry, when `cpsReference` is defined, then it exists with `provenance: 'inference'` and the example shape the scope itself gives (`XX/XX/XXXXXX/XX`, introduced there with "e.g.").
- Given the eleven templates, when they are searched, then **no template declares a CPS reference field**, so nothing references the format.
- Given the suite, when it runs, then a check asserts the registry entry exists and that no template references it — so if a CPS reference field is added later, that check fails and forces the rule to be wired up deliberately.
- Given `open-questions.md`, when it is read, then the gap is recorded: the scope asks for a format check on a datum the product holds only as a **case value** (`cpsReference` is a `CaseFieldPath`), never as a user-entered field.

## Notes & Constraints

- This story deliberately delivers a registry entry and a test, not a feature. The alternative — inventing a
  CPS reference box on an MG form so the scope's rule has somewhere to live — is exactly the failure mode
  CLAUDE.md rule 1 exists to prevent.
- If the decision is that the case's `cpsReference` should be validated where it is *displayed*, that is a
  different piece of work: the value is read-only, supplied by the case, and not something the solicitor can
  correct on the form.

- Rule engine: `libs/shared/src/lib/validation.ts` (new, pure). Types:
  `libs/shared/src/lib/form-template.types.ts`. Rules on fields: `form-templates.ts`.
- **No invented format.** A format may be `error` severity only if its provenance is `documented` with a
  cited source. Everything else is advisory. This is enforced by `severityFor()` and by
  `npm run conformance` — not by good intentions.
- **Additive only:** never rename or delete a field id; bump `templateVersion` on any template whose rules
  change; run `npm run orphan-scan` around any id change.
- Reuse the shared renderer. Do not special-case a form code; a rule is declared on the field that owns it.
- After changing `libs/shared`, **restart the API** — the nest watcher does not pick up shared-lib rebuilds.
- Full mechanism and business rules: `docs/usecases/uc-05/prd.md` (§4 and §8).
