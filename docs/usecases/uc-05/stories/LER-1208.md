# LER-1208 — Severity model — an unsourced rule cannot block

_UC-05 Field Validation · epic: `docs/usecases/uc-05/epic.md` · PRD: `docs/usecases/uc-05/prd.md`_

_DevOps Bot ticket **LER-1208** (Story, To Do) · build stage order: story 02 of 16._

## User Story
As a defence solicitor, I want a rule we are unsure about to advise rather than block, so that the product never refuses a value that is actually correct on a document going to court.

## Acceptance Criteria
- Given a format with `provenance: 'documented'` and a non-empty `source`, when `severityFor` is called, then it returns `error`.
- Given a format with provenance `likely` or `inference`, when `severityFor` is called, then it returns `advisory` regardless of what the template asked for.
- Given an `error`-severity rule that fails, when the field is blurred, then the inline message appears, the control is invalid, and the field does not count towards required-field progress.
- Given an `advisory` rule that fails, when the field is blurred, then a hint appears, the control stays **valid**, progress is unaffected, and the draft still saves.
- Given a template declaring `severity: 'error'` on a format whose provenance does not permit it, when `npm run conformance` runs, then it fails, naming the field and the format.
- Given the same template, when the app runs anyway, then `severityFor` still returns `advisory` — the gate is a second line of defence, not the only one.

## Notes & Constraints

- This is the story the whole epic rests on. Everything else can be re-litigated; this cannot, because it is
  what makes "never invent a statutory format" a mechanism rather than a promise.
- Two layers on purpose: the runtime function cannot be bypassed by editing a template, and the conformance
  gate makes the mistake visible in CI rather than silently downgraded.
- An advisory finding is still recorded in the audit count, so proceeding past one is auditable.

- Rule engine: `libs/shared/src/lib/validation.ts` (new, pure). Types:
  `libs/shared/src/lib/form-template.types.ts`. Rules on fields: `form-templates.ts`.
- **No invented format.** A format may be `error` severity only if its provenance is `documented` with a
  cited source. Everything else is advisory. This is enforced by `severityFor()` and by
  `npm run conformance` — not by good intentions.
- **Additive only:** never rename or delete a field id; bump `templateVersion` on any template whose rules
  change; run `npm run orphan-scan` around any id change.
- Reuse the shared renderer. Do not special-case a form code; a rule is declared on the field that owns it.
- After changing `libs/shared`, **restart the API** — the nest watcher does not pick up shared-lib rebuilds.
- Full mechanism and business rules: `docs/usecases/uc-05/prd.md` (§4 and §8).
