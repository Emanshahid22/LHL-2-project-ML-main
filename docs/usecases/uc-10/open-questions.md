# UC-10 — open questions and human-ruling flags

_Raised at Phase 1 (planning), before any code — the LER-1200 lesson from
UC-09: rulings queue early, not at PR time. Numbered for reference from the
PRD and the eventual PR body._

## 1. "Cloud storage" — interpretation to confirm (ruling: LOW risk)

The scope's actor list says "cloud document storage" and its post-condition
"All versions preserved in cloud storage". What exists is the UC-09
encrypted document store on the deployed environment's volume (Railway) —
provisioned under LER-1202 ("Provision cloud environment with encryption at
rest", **Done**), which reads as prior acceptance of that environment as
"the cloud". UC-10 proceeds on that interpretation: **the encrypted store
of the deployed environment IS the cloud storage**; no S3-class external
service is introduced. Needs a nod, not a design: if the client expects an
external object store, that is a storage-adapter change behind the existing
opaque `storageKey` and should be its own ticket.

## 2. External case file system — BLOCKED dependency, escalate now

The scope's actors include a "case file system", and the tracker still has
**"Obtain case management system API docs and test access" open (To Do)**.
No external CMS can be integrated without those docs. UC-10 therefore
attaches documents to the INTERNAL case model (`Case` rows, the
`cases/:id` Documents section) — which the rest of the scope treats as the
case file throughout UC-01..09. External CMS attachment is out of scope
(PRD §14) until that ticket unblocks. **Human action: chase the API docs or
confirm internal-only is the deliverable.**

## 3. Retention / erasure vs append-only — needs a data-protection ruling

LER-1182: "No version is ever deleted by any user action — append-only
constraint enforces this." Criminal-case documents also live under data
protection law (UK GDPR / DPA 2018 Part 3): a subject-access or erasure
demand, or a firm's retention schedule, may one day require destruction
that "no user action deletes" cannot express. UC-10 builds the append-only
rule exactly as ticketed and defers any erasure/retention mechanism to a
**practitioner/DPO ruling** — the same class of call as MG11's declaration
wording (rule 8: legal calls are not implementation choices). Flag to the
human queue now.

## 4. Sensitive material at the widened retrieval boundary — decision taken, confirm

Case attachment makes a stored document reachable by every case-access
holder, not just its generating owner. A version whose render includes MG6D
content (generated by a permitted caller) must not flow to a caller without
`sensitiveMaterialAccess` just because they can see the case. The scope is
silent; UC-09's `sensitive-rendering` precedent (LER-2398) says silence at
a security boundary is not permission. **Design decision taken in the PRD
(§4): serve-time re-check + diff redaction + `containsSensitive` recorded
at mint.** Listed here so the decision is visible for veto, not because we
propose to wait.

## 5. "Retried automatically on next login" — deviation, minor

The scope's error flow imagines case attachment failing independently of
storage and being retried at login. In this architecture attachment is a
column in the same transaction as the version row — it cannot fail
separately, and the demo auth model has no login lifecycle to hang a retry
on. The honest equivalent (PRD §10): standalone/unlinked state is always
visible with the link action available. Recorded as a deviation in the
eventual PR body; no ruling needed unless the client disagrees.
