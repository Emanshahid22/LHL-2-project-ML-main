# LER-1174 — Reopen creates editable copy

_Client ticket **LER-1174** (Story, To Do) · delivering ticket: to be created after pack review · build order: story 5 of 16, stage 2._

## User Story
As a defence solicitor needing to amend a finalised form, I want reopening to produce a new editable copy, so that the finalised original is never edited in place.

## Acceptance Criteria
- Given a FINALISED current version, when `POST /drafts/:id/reopen`, then a new DRAFT mints copying all values, same form/case, lineage carried, `amendedFromId` set; response carries the new draft id; audit `FORM_REOPENED`.
- Given the new copy, when edited and reviewed, then the normal UC-02..08 flow applies — it is a first-class draft.
- Given a draft that is not FINALISED, not current, or whose lineage already has an open copy, when reopen is called, then 409 with a reason.

## Notes & Constraints
- One open amendment per lineage — the fork guard is a transaction, not a UI rule (PRD §4/§10).
- Values copy includes sensitive keys — the copy holds what the original holds; UC-07 read rules apply to it identically.

## Definition of Done
- e2e: reopen → edit → the original's values unchanged; double-reopen 409.
