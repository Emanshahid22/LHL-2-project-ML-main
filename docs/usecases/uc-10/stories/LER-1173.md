# LER-1173 — Document entry metadata

_Client ticket **LER-1173** (Story, To Do) · delivering ticket: to be created after pack review · build order: story 4 of 16, stage 3._

## User Story
As a defence solicitor scanning a case's Documents section, I want each entry to show form type, version number, created date, creator and status, so that one row summarises each document without opening it.

## Acceptance Criteria
- Given an attached lineage, when the Documents section renders, then its primary row shows: form code + title, `V<n>` + label, created date (DD/MM/YYYY display), created by, and status "Final".
- Given the API DTO, when fetched, then the same fields are present and typed — the UI displays, never derives.
- Given a lineage with amendments, when listed, then the primary row is the CURRENT version (DoD line 4) and prior versions appear only in the drawer.

## Notes & Constraints
- Dates: ISO storage, DD/MM/YYYY display (rule 7). No defendant data in the row's identifiers or links (Global DoD #11).

## Definition of Done
- DTO unit-shaped; e2e asserts the row's five fields via data-testids.
