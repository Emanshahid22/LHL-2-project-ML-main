# LER-1186 — Archive search and retrieval

_Client ticket **LER-1186** (Story, To Do) · delivering ticket: to be created after pack review · build order: story 16 of 16, stage 3._

## User Story
As a defence solicitor with a growing archive, I want to find forms by case, form type, date and status, so that the archive is usable at volume.

## Acceptance Criteria
- Given the archive view, when filtered by case, form type, date range or status (any combination), then only matching lineages list, current-version metadata shown.
- Given a standalone lineage, when filtering by case, then it appears only under "no case" — never mis-bucketed.
- Given filters, when applied, then they are query parameters on `GET /archive` — server-side filtering, not client-side sieving of everything.

## Notes & Constraints
- Search is a read — no audit row (the trail records writes only). Indexes on `lineageId`/`caseId` carry the query (PRD §9).

## Definition of Done
- e2e: each filter alone plus one combination; standalone bucketing check.
