# UC-10 — Form Archive & Case Attachment — PRD (as planned)

_Written before the build (Phase 1). Where the build later deviates, the PR
body records the deviation against this text — this file is not rewritten._

## 1. Summary

On every successful PDF generation the document is filed as a **version** in
an append-only archive: case-linked forms attach to the case's Documents
section under an "MG Forms" folder; standalone forms land in the user's
personal archive and can be case-linked later. Re-opening a finalised form
creates a new editable copy in the same **lineage** while the original locks;
the copy re-runs UC-08 and UC-09 and its generation mints the next version
(V2, V3, …; labels "Original", "Amendment 1", …). Prior versions are
downloadable forever, never editable, never deletable by any user action. A
drawer lists the versions; a field-level diff compares any two; the archive
is searchable. Retrieval of a version that carries rendered MG6D content
re-checks the UC-07 permission at serve time.

## 2. Scope requirements (verbatim)

From <https://lhl-agents.netlify.app/mg-forms-scope/>, UC-10 "Form Archive &
Case Attachment":

> Completed forms stored per case in cloud storage and attached to the case
> file Documents section. Version history maintained for each form.
> Amendments create a new version; all prior versions are preserved and
> accessible.

Pre-conditions: "PDF generated (UC-09)" · "Case file exists and is
accessible (for case-linked forms)" · "Cloud storage service available".

Main flow:

> 1. On PDF generation, form is automatically attached to the case file's
>    Documents section under an "MG Forms" folder
> 2. Document entry shows: form type, version number (V1), created date,
>    created by, and status (Final)
> 3. User can re-open a finalised form for amendment: system creates a new
>    editable copy; original version is locked
> 4. Amended form goes through quality check (UC-08) and PDF generation
>    (UC-09) again
> 5. On amendment PDF generation: new version (V2, V3, etc.) created and
>    attached; prior versions remain accessible in the version history drawer
> 6. Version history drawer: each version shows its number, generated date,
>    generated by, and a download link for that version's PDF
> 7. Version labels: "Original", "Amendment 1", "Amendment 2", etc. for
>    clarity

Alt flow: "Standalone form (not case-linked): form stored in the user's
personal MG Forms archive (not attached to a case). User can manually link
it to a case later from the archive view."

Error handling: "Cloud storage write fails — PDF generated locally for
download; retry option for storage upload. Case file attachment fails — form
stored in user's MG Forms archive with a 'Pending case attachment'
indicator; retried automatically on next login."

Post-conditions: "All versions preserved in cloud storage. Case file
Documents section updated. Prior versions accessible but not editable.
Defendant personal data absent from storage paths."

Definition of Done (quoted verbatim in the PR body when built):

> - Version history correctly preserves all prior versions on amendment —
>   tested through 3 amendment cycles
> - Prior versions are accessible for download but cannot be re-opened for
>   editing
> - Standalone form manual case-linking works correctly from the archive view
> - Case file Documents section shows the correct current version as the
>   primary entry

Applicable Global DoD: #9 "Version history correctly preserves all prior
versions on amendment" · #11 "No defendant personal data in file names or
storage paths" · #12 "All MG form PDFs encrypted at rest — verified via
storage metadata".

## 3. What already exists

- **UC-09 document pipeline** (merged, PRs #194/#197): `POST /drafts/:id/pdf`
  gated by the UC-08 engine, off-request render, AES-256-GCM
  content-addressed storage (`GeneratedDocument` rows; twin content shares
  ciphertext), verify-then-serve downloads (410 on tamper), PII-free
  filenames/keys enforced by `tools/pii-scan`, and — the hook this UC was
  promised — `archiveStatus: 'pending-uc10'` on every row (deviation D4).
- **Draft lifecycle** (UC-08): `DRAFT → REVIEWED → FINALISED`; edits refused
  on anything else (`drafts.service.ts`); `finalise()` re-runs the engine at
  the boundary and audits `FORM_FINALISED`. The `ARCHIVED` status string is
  reserved in the schema comment but unused — UC-10 claims it.
- **Case model**: `Case` with `CaseAccess` rows; `FormDraft.caseId` nullable
  — case-linked vs standalone already exists at the draft level.
- **UC-07 sensitive machinery**: caller-scoped `redactSensitiveValues`
  before binding; `user.sensitiveMaterialAccess`; red reserved; MG6D content
  never in logs/filenames/keys. Renders by a permitted caller audit
  `SENSITIVE_SECTION_VIEWED` (`via: 'document-render'`).
- **Audit trail** (writes only): `PDF_GENERATED/RETRIED/FAILED`,
  `DOCUMENT_DOWNLOADED`, `DOCX_EXPORTED`, `DOCUMENT_INTEGRITY_FAILED`,
  `FORM_FINALISED`, ….
- **Web**: routes `''` (home), `cases/:id`, `drafts/:id`; PdfControls on a
  finalised/clean-reviewed draft.

## 4. Mechanism

**Lineage, not copies of copies.** A new `FormLineage` concept ties a form's
life together. Implemented additively:

- `FormDraft` gains nullable `lineageId` (root draft's id for every member,
  including the root itself, set lazily on first archive/reopen) and
  nullable `amendedFromId` (the draft this copy was reopened from).
- New model `ArchivedVersion`: `{ id, lineageId, versionNumber, label,
  cycle, draftId, documentId (pdf), docxDocumentId?, caseId?, userId,
  valuesSnapshotJson, containsSensitive, createdAt }` — append-only, unique
  `(lineageId, versionNumber)`.

**Version minting.** _(Amended at the Phase-1 review gate, condition 1 —
the original text made minting content-conditional; that was rejected.)_
**Version identity is ROW-level, not content-level**: every successful
generation job appends the next `versionNumber` — an amendment finalised
with content identical to the prior version still mints a new row, pointing
at the same stored file (the DoD's "amendments create a new version" is
about history, and content-addressing is about bytes). `cycle` = the
draft's amendment depth (root = 0). `label` = `cycle === 0 ? 'Original' :
'Amendment ' + cycle` — both assigned by the shared `planVersionMint()`,
which takes no content input at all, so byte-identity cannot suppress a
mint by construction. The GeneratedDocument's `archiveStatus` stub becomes
real: `'attached'` (case-linked), `'personal'` (standalone).

**Reopen.** `POST /drafts/:id/reopen` — valid only when the draft is
`FINALISED`, is the lineage's CURRENT version's draft, and no open
(DRAFT/REVIEWED) member exists on the lineage (else 409). Creates a new
FormDraft copying `valuesJson` (all of it, sensitive keys included — same
data the original holds), same `formCode`/`caseId`, `status: 'DRAFT'`,
lineage carried, `amendedFromId` set; the original stays `FINALISED` (already
edit-locked) and flips to `ARCHIVED` when the amendment's first version
mints (superseded = locked hardest). Audits `FORM_REOPENED`.

**Attachment.** Case-linked versions are rows with `caseId` — the case
Documents section is a query, not a copy. Standalone lineages: `caseId`
null; `POST /archive/lineages/:id/link { caseId }` (owner + case access
required) back-fills `caseId` across the lineage's versions and drafts,
audits `CASE_LINKED`. Un-linking does not exist (append-only spirit; a
mislink is corrected by linking to the right case, both acts audited).

**Diff.** `GET /archive/lineages/:id/diff?from=V&to=V` compares the two
versions' `valuesSnapshotJson` field-by-field against the template's field
labels: added / removed / changed, with the values. Sensitive (MG6D) fields
are redacted from the diff for non-permitted callers by the same shared
`redactSensitiveValues`; a permitted caller's diff over sensitive changes
audits `SENSITIVE_SECTION_VIEWED` (`via: 'version-diff'`).

**Serve-time sensitive re-check.** `ArchivedVersion.containsSensitive` is
recorded at mint (the render model already knows). The download path refuses
(403, audited) a sensitive-bearing version to a caller without
`sensitiveMaterialAccess`, regardless of case access — attachment widens the
audience, the permission does not follow it.

## 5. API surface

- `POST /drafts/:id/reopen` → 201 `{ draftId }` · 409 lineage has an open
  copy / not current / not finalised · 404 not owned.
- `GET /cases/:id/documents` → the Documents section: MG Forms folder,
  grouped by lineage, primary entry = current version, each with metadata
  (form type, `V<n>`, label, created date/by, status `Final`).
- `GET /archive` → the caller's personal + case-linked lineages; filters
  `formCode`, `caseId`, `status`, `from`, `to` (LER-1186).
- `GET /archive/lineages/:id/versions` → the drawer: every version's number,
  label, generated date, generator, page count, size, download availability.
- `GET /archive/lineages/:id/diff?from=&to=` → field-level diff (redaction
  rules above).
- `POST /archive/lineages/:id/link` `{ caseId }` → 200 · 409 already linked ·
  403 no case access.
- Downloads reuse UC-09's `GET /documents/:id/download|preview` (ownership
  widened to case-access holders for attached versions + the sensitive
  re-check; the verify-then-serve and filename rules unchanged).
- No DELETE anywhere on the archive surface (LER-1182).

## 6. Data Model & Schema

Additive only (rule 3):

- `FormDraft` + `lineageId String?` (indexed), + `amendedFromId String?`.
- New `ArchivedVersion` table as §4; `@@unique([lineageId, versionNumber])`;
  `valuesSnapshotJson String` (same trust level as `FormDraft.valuesJson`,
  which already holds these values); `containsSensitive Boolean`;
  `contentHash String` denormalised from the document row at mint, so a
  version's byte-integrity is assertable without trusting the join.
- **"Re-serve" applies to STORAGE, never to version rows** (Phase-1 review,
  condition 1): the UC-09 twin-row discipline carries over unchanged — an
  identical-content version shares the immutable encrypted file (never
  re-encrypted, never byte-flipped by any test; a tamper test renders
  unique content, the ff66d1b lesson) while its GeneratedDocument row
  carries its own contentHash/authTag pairing, and the ArchivedVersion row
  is always new. History never deduplicates.
- `GeneratedDocument.archiveStatus` values become `'attached' | 'personal'`
  for new rows (`'pending-uc10'` remains only on pre-UC-10 rows; dev.db
  baseline has zero document rows, so no backfill is needed anywhere).
- No column renames or deletions; `npm run orphan-scan` unaffected
  (template ids untouched).

## 7. Data Flow & Integrations

Generation (UC-09 job succeeds) → mint-or-reuse version (same transaction
as the document row) → attach by `caseId` presence → audit
`DOCUMENT_ARCHIVED { lineageId, versionNumber, attached }`. Reopen → copy →
normal UC-02..08 editing flow → finalise → generate → next version. The
only cross-system integration is the INTERNAL case model; the external case
management system remains out of scope (its API-docs ticket is still open
— `open-questions.md` #2). Storage stays the UC-09 encrypted store; no new
storage backend ("cloud storage" interpretation recorded in
`open-questions.md` #1).

## 8. Client

- `cases/:id` gains a **Documents** section: "MG Forms" folder listing one
  primary row per lineage (current version) with the §5 metadata; a row
  expands into the **version history drawer** (number, label, date,
  generator, per-version download).
- **Archive view** (new route `archive`): the personal + case-linked
  lineages with the four filters; standalone rows carry a **Link to case**
  action (dialog: case picker) — DoD line 3 lives here.
- **Reopen for amendment** action on a finalised form (and on the archive's
  current version): confirms, then navigates to the new editable copy.
  Prior-version rows have download only — no edit affordance exists, and
  the API refuses anyway (LER-1181).
- **Diff view**: pick two versions in the drawer → field-level change list.
- Draft-band and verification rules unchanged (documents render exactly as
  UC-09 made them; UC-10 never re-renders old bytes).
- Amber advisories; red stays reserved for UC-07 sensitive UI.

## 9. Security & Performance

- **Encryption at rest unchanged** (Global DoD #12): UC-10 stores no new
  document bytes — versions reference UC-09's encrypted, content-addressed
  files. Values snapshots live in the DB exactly as draft values already do.
- **PII-free paths** (Global DoD #11): version rows add no filenames or
  storage keys; download filenames stay `<formCode>-draft-<yyyymmdd>.<ext>`
  … extended with `-v<N>` (still no case data). `tools/pii-scan` grows an
  archive-surface walk (version rows, lineage ids, link metadata) and stays
  fail-closed in CI.
- **Sensitive boundary** (UC-07): serve-time re-check (§4); diff redaction;
  `containsSensitive` recorded at mint from the render model, never
  recomputed by decrypting stored bytes; no MG6D content in audit metadata,
  job rows, labels or search indexes.
- **Authorization**: personal archive is owner-only; attached versions
  readable by case-access holders (minus the sensitive re-check); reopen and
  link are owner-only writes.
- **Performance**: the Documents section and drawer are indexed lookups
  (`lineageId`, `caseId`); the diff is O(fields) on two JSON snapshots —
  no PDF parsing at request time; no render work anywhere in UC-10 paths.

## 10. Failure modes

- Storage write fails during generation → UC-09's job pipeline already
  fails the job (`PDF_FAILED`) with retry (`PDF_RETRIED`); no version row
  mints without a stored document (same transaction). The scope's "PDF
  generated locally for download" imagines a client-side fallback that
  contradicts the encrypted-store design — recorded as a deviation, not
  built.
- "Case file attachment fails … retried on next login": attachment is a
  DB column in the same transaction as the version row — it cannot fail
  independently of the write itself. The honest equivalent ships:
  standalone lineages show a "not case-linked" state with the link action
  always available. Deviation recorded.
- Reopen races (two tabs): the open-amendment check is a guarded
  transaction; second reopen → 409.
- Link races: unique current-`caseId` guard; relink audited.
- Tampered stored version → UC-09's verify-then-serve 410 +
  `DOCUMENT_INTEGRITY_FAILED`, version row untouched (history preserved
  even when bytes are damaged — the row is the record).
- Diff across template versions (draft amended after a template bump): the
  diff maps ids through both versions' `templateVersion` field sets; ids
  absent from one side render as added/removed, never crash.

## 11. Business rules

- Append-only: no user action deletes or mutates a version row (LER-1182);
  no un-link; no re-number.
- Version numbers are engine-assigned, monotonic per lineage (LER-1177);
  labels derive from the amendment cycle: `Original`, `Amendment N`
  (scope step 7). If one cycle ever produces multiple versions (values
  edited and regenerated within a REVIEWED window before finalising), the
  versions share the label and are disambiguated by number and date —
  recorded interpretation.
- Only the lineage's current, FINALISED version can be reopened; one open
  amendment at a time (LER-1174/1175).
- An amendment is a first-class draft: UC-08 gate and UC-09 generation run
  in full, no shortcut path (LER-1176).
- Superseded drafts flip to `ARCHIVED` — locked against edit AND reopen.
- Sensitive-bearing versions serve only to UC-07-permitted callers (§4).
- Standalone forms are never orphaned: they exist in the personal archive
  from their first generation (LER-1184).

New spec `e2e/uc10-archive.spec.ts` with a dedicated fixture case
(registered in `e2e/FIXTURES.md`; the frozen Nadia Kowalczyk UC-09 fixture
is untouchable). Sketch, one check per client criterion plus the boundary
stories:

- generation attaches V1 "Original" to the case Documents section with full
  metadata (LER-1172/1173, DoD 4 primary-entry check).
- reopen creates an editable copy, original locked via API (LER-1174/1175);
  second reopen 409s; editing a prior version's draft 409s (LER-1181, DoD 2).
- **three amendment cycles** (DoD 1 verbatim): V1→V2→V3→V4, all prior
  versions listed and downloadable, byte-served PDFs text-checked
  per-version (wrap-proof `flat()` helpers as in uc09).
- amendment refuses generation until UC-08 passes (LER-1176).
- drawer metadata + per-version download (LER-1178/1179/1180).
- append-only: no deletion surface; direct API attempts 404/405 (LER-1182).
- diff between two versions shows the changed field, old and new value
  (LER-1183); sensitive fields redacted for the unpermitted caller.
- standalone form lands in personal archive; manual link attaches its whole
  history to the case (LER-1184/1185, DoD 3).
- search by case / form type / date / status (LER-1186).
- sensitive-bearing version: permitted caller downloads (audited), revoked
  caller 403s (sensitive-retrieval story).
- audit rows for `DOCUMENT_ARCHIVED`, `FORM_REOPENED`, `CASE_LINKED`.

Unit layer (`libs/shared/test`): version-label derivation, diff algorithm
(including cross-template-version), redaction of diff output. Suite
discipline: dev.db baseline verified first (35 drafts / 76 audit / 0 acks /
