# LER-1126 — MG6D auto-activation from the sensitive classification

_UC-07 Sensitive Material Handling · epic: `docs/usecases/uc-07/epic.md` · PRD: `docs/usecases/uc-07/prd.md`_

_Client ticket **LER-1126** (Story, To Do) · delivering ticket: **LER-1240** · build order: story 01 of 15, stage 1._

## User Story
As a defence solicitor, I want the MG6D sensitive-material section to activate by itself the moment any schedule item is classified Sensitive, so that sensitive handling is never something I have to remember to switch on.

## Acceptance Criteria
- Given the shared types, when this story ships, then `FormFieldDefinition` carries an optional `sensitive: true` declaration (declared, never inferred) and MG6 is v5 with a `sensitiveScheduleItems` group (`section` "MG6D — Sensitive material schedule", `sensitive: true`), whose three columns — description, location, reason sensitive — each cite the Manual of Guidance v11 MG06D entry as `provenance: 'documented'`.
- Given an MG6 draft with no sensitive rows, when the form renders, then no MG6D section appears (the declaration is dormant).
- Given the user classifies any schedule row Sensitive, when the select changes, then the MG6D section appears immediately (live `hasSensitiveRow` on the current form value) — no save required, no manual step, every time without exception.
- Given the draft is saved, when the server recomputes derived flags, then `hasSensitiveMaterial` is true and `sensitiveSection.active` is true on the DTO — the server, not the client, is authoritative.
- Given the last sensitive row is reclassified or removed, when the form updates, then the section deactivates; stored MG6D values are preserved dormant and return on reactivation (open-questions Q4).

## Notes & Constraints
- Triggered from UC-04's `sensitivityFlag`, never selected manually and never keyed off the form code
  (the designation is disputed — LER-1205; everything follows the field declaration).
- ADDITIVE: MG6 v4 → v5; no id renamed; `orphan-scan` clean; `verification` stays `'unverified'`.
- No column beyond the three the MoG documents — the prosecutor's boxes are open-questions Q5, and an
  item-number column is not invented (row numbering is positional, UC-04's engine).
- Conformance gains a `sensitive-declaration` tier: top-level only, `section` required, one section per
  template, no `mapsTo` on sensitive fields, and a declaring template must have a `sensitivityFlag`
  group. Self-tests plant defects in both directions.
