# LER-1132 — PII reminder panel

_UC-07 Sensitive Material Handling · epic: `docs/usecases/uc-07/epic.md` · PRD: `docs/usecases/uc-07/prd.md`_

_Client ticket **LER-1132** (Story, To Do) · delivering ticket: **LER-1246** · build order: story 07 of 15, stage 3._

## User Story
As a defence solicitor, I want the Public Interest Immunity steps in front of me while I work on sensitive material, so that the process the material may trigger is part of the form, not tribal knowledge.

## Acceptance Criteria
- Given a permitted user with the section confirmed, when the section renders, then a PII reminder panel renders alongside it listing the steps of the Public Interest Immunity process.
- Given the steps, when they ship, then each carries its citation (PRD §6 — MoG v11 MG06D entry) and no step ships uncited; the panel states its own limits and the unverified status.
- Given the panel, when the user acknowledges it, then the acknowledgement is persisted per user per draft (kind PII_STEPS, wording hash) and audited — the scope's post-condition "PII reminder acknowledged and recorded".
- Given a prior acknowledgement by this user for this draft, when the panel renders, then it shows the acknowledged state (cadence decision: open-questions Q6).
- Given a locked user, when the section renders locked, then no PII content is in the payload.

## Notes & Constraints
- PII here is Public Interest Immunity — never expand it as personally identifiable information anywhere
  in UI copy or code comments; the collision is exactly the kind of thing that misleads a future reader.
- The practice-direction link is LER-1133's half of this panel.
