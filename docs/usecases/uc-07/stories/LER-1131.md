# LER-1131 — Confirmation not bypassable at the API

_UC-07 Sensitive Material Handling · epic: `docs/usecases/uc-07/epic.md` · PRD: `docs/usecases/uc-07/prd.md`_

_Client ticket **LER-1131** (Story, To Do) · delivering ticket: **LER-1245** · build order: story 06 of 15, stage 2._

## User Story
As a compliance-minded practice, we want the API itself to reject any edit of sensitive fields that does not carry a recorded confirmation, so that the gate holds even against a client we did not write.

## Acceptance Criteria
- Given a direct `PATCH /api/drafts/:id` whose values contain any sensitive-declared key, when no `sensitiveConfirmationId` accompanies it, then 403 — the values are not stored, and `SENSITIVE_ACCESS_DENIED` is audited with the caller's identity.
- Given the same request with an invented id, a confirmation belonging to another user, or one belonging to another draft, when it is validated, then 403 all the same — the confirmation must be THIS user's, for THIS draft, of kind HANDLING_INSTRUCTIONS.
- Given a caller without the permission, when their request touches sensitive keys, then 403 regardless of any confirmation id.
- Given the legitimate flow (permitted user, real confirmation), when the save lands, then 200, values stored, `SENSITIVE_SECTION_EDITED` audited alongside `DRAFT_SAVED`.
- Given a request that does NOT touch sensitive keys, when a locked or unconfirmed user autosaves, then the save succeeds AND the stored sensitive values survive untouched (merge-preserve — open-questions F1).
- Given the suite, when DoD line 2 is proven, then the proof is a REAL HTTP call against the running API asserting the rejection, not a unit test of the guard function.

## Notes & Constraints
- The guard lives in `DraftsService.update()` — the NestJS layer, the single write path. "Touched" means
  the key is present in the request: present-but-unchanged is still an edit request and still rejected
  without a confirmation (D1 records why 403, not 422).
- Merge-preserve is the other half of this story: rejecting edits while silently erasing on non-edits
  would be worse than no gate.
