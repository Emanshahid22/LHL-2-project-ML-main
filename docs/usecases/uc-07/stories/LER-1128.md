# LER-1128 — Handling instructions pre-populated and read-only

_UC-07 Sensitive Material Handling · epic: `docs/usecases/uc-07/epic.md` · PRD: `docs/usecases/uc-07/prd.md`_

_Client ticket **LER-1128** (Story, To Do) · delivering ticket: **LER-1242** · build order: story 03 of 15, stage 2._

## User Story
As a defence solicitor, I want the mandatory handling instructions already present and impossible to edit or blank, so that what I confirm is what everyone else confirmed too.

## Acceptance Criteria
- Given an active section and a permitted user, when the section renders, then the handling-instructions block is populated from the server-owned constant — the user cannot edit, clear or replace it (no input element renders it).
- Given the instructions wording, when it ships, then every sentence carries a citation (PRD §6: MoG v11 MG06D; Home Office criminal-casefiles standard v2.0) and the block ends with an explicit unverified notice — no uncited sentence ships (open-questions Q3).
- Given the shared module, when the wording is defined, then `sensitiveWordingHash()` pins it (SHA-256, the MG11-declaration discipline) and every acknowledgement row records the hash it acknowledged.
- Given a locked user, when the section renders, then the instructions are NOT in the payload — the read-only block is content, and locked users receive no content.

## Notes & Constraints
- Server-owned means exactly that: no endpoint accepts instruction wording from a client, and the DTO is
  the only way it reaches the browser.
- "Cannot be skipped or blanked" is delivered structurally: there is no state in which the section is
  editable without the instructions having been rendered and confirmed (LER-1129/1130/1131).
