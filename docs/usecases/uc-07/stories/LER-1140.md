# LER-1140 — QA — Definition of Done checks

_Client ticket **LER-1140** (Story, To Do) · delivering ticket: **LER-1254** · build order: story 15 of 15, stage 4._

## User Story
As the project, we want the four scope DoD lines proven by named, repeatable checks, so that "done" is a property of the suite rather than a claim in a PR.

## Acceptance Criteria
- Given DoD line 1 ("Sensitive material flag (MG6D) triggers the mandatory handling instruction every time without exception"), when the suite runs, then checks prove activation on row classification immediately, on a second independent draft, and after deactivate/reactivate — with the instructions block present each time.
- Given DoD line 2 ("Confirmation cannot be bypassed at API level — tested with a direct API call without the confirmation flag"), when the suite runs, then a real HTTP PATCH without the confirmation is asserted rejected (403), plus the foreign-id, wrong-user and no-permission variants.
- Given DoD line 3 ("All MG6D access events appear in the audit trail with correct user identity and timestamp"), when the suite runs, then view and edit rows are read back from the database and their `userId` and `createdAt` asserted.
- Given DoD line 4 ("Sensitive items are absent from non-sensitive schedule exports — verified with a test export"), when the suite runs, then a real export is fetched and the sensitive item's text asserted absent from the whole body.
- Given everything above, when the suite completes, then every pre-existing check is green, every pre-existing `data-testid` intact, conformance (with the new sensitive-declaration self-tests) and orphan-scan pass, and test drafts are cleaned from dev.db.

## Notes & Constraints
- "Automated test plus targeted security review": the security-review pass covers the guard order
  (permission before confirmation before storage), redaction completeness across all four DTO paths,
  and the merge-preserve path — its findings land in this pack, fixed or recorded.
- Run the full suite twice on dev.db and once on a freshly seeded throwaway DB (CI condition).

## Definition of Done
- Delivered against the acceptance criteria above
- `npm run test:e2e` green and both builds pass
- `npm run conformance` and `npm run orphan-scan` pass
- Every existing `data-testid` intact
- Test drafts cleaned from `apps/api/prisma/dev.db`
