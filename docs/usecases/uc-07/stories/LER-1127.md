# LER-1127 — Red 'Sensitive — Restricted Access' banner

_UC-07 Sensitive Material Handling · epic: `docs/usecases/uc-07/epic.md` · PRD: `docs/usecases/uc-07/prd.md`_

_Client ticket **LER-1127** (Story, To Do) · delivering ticket: **LER-1241** · build order: story 02 of 15, stage 1._

## User Story
As a defence solicitor, I want the sensitive section marked with an unmissable red restricted-access banner, so that the change of handling regime is impossible to overlook.

## Acceptance Criteria
- Given the MG6D section is active, when it renders in any of its states (locked, unconfirmed, editable), then a banner reading "Sensitive — Restricted Access" heads the section.
- Given the design tokens, when this story ships, then `_tokens.scss` fills its reserved sensitive-red slot with `--mg-sensitive-*` tokens and the banner uses only those tokens — no hardcoded colour anywhere.
- Given the rest of the app, when this story ships, then red appears ONLY on UC-07 surfaces: amber advisories, the validation danger palette and the per-form accents are byte-identical.
- Given UC-04's amber header chip (`data-testid="sensitive-material-indicator"`), when the section is active, then the chip still renders exactly as before — UC-07 adds, it does not replace.

## Notes & Constraints
- The tokens file has carried the comment "The sensitive red is deliberately NOT defined here — it is
  reserved for UC-07" since UC-03. This story redeems that reservation; update the comment.
- Unmissable means state, not decoration: the banner is part of the section component and renders in
  every state including locked.
