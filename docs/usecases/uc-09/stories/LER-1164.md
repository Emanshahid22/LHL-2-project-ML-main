## User Story
As the chain's next link, we want every generated document to record its pending archive attachment the way UC-08 stubbed UC-09, so that UC-10 has a real seam to fill and no UI pretends an archive exists before it does.

## Acceptance Criteria
- Given a generated document, when stored, then its row carries `archiveStatus: 'pending-uc10'` and, for case-linked drafts, the `caseId` the archive will attach under.
- Given the UI after generation, when it reports success, then it states plainly that archive attachment arrives with UC-10 (a testid-carrying stub line, the UC-08 precedent verbatim in spirit).
- Given UC-10's future work, when it lands, then flipping the stub is data + one UI line — nothing in this story's design assumes more.

## Notes & Constraints
- D4: the scope's "stored in the case document archive (UC-10) automatically" cannot be true before UC-10 exists; the stub records the obligation without faking the feature.

## Definition of Done
- Delivered against the criteria; e2e asserts the status field and the stub line; full gate set green
