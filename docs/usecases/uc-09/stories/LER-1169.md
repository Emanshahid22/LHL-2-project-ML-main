# LER-1169 — Failure never touches the draft

_UC-09 PDF Generation & Formatting · epic: `docs/usecases/uc-09/epic.md` · PRD: `docs/usecases/uc-09/prd.md`_

_Client ticket **LER-1169** (Story, To Do) · delivering ticket: **LER-2389** · build order: story 15 of 26, stage 2._

## User Story
As the owner of the entered data, we want a failed generation to leave the draft byte-identical — values, version, status, audit acknowledgements — so that no rendering fault can ever cost entered work.

## Acceptance Criteria
- Given a draft snapshot taken before an induced render failure, when the job fails, then the draft row (values, `version`, status) and its acknowledgements are byte-identical afterwards — asserted by direct comparison, not by absence of complaints.
- Given the failure path, when it executes, then it writes only job state and audit rows — code-reviewably: the failure branch holds no draft mutation, mirroring PR #144's "nothing until the transition has won" discipline.
- Given a failure mid-encryption or mid-store, when it happens, then no partial file remains (write-then-rename or equivalent atomicity).

## Notes & Constraints
- This is the render-side sibling of the finalise audit-ordering fix: the trail and the store must never claim what did not happen.

## Definition of Done
- Delivered against the criteria; snapshot-compare e2e check; full gate set green
