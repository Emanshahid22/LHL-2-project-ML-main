# LER-1017 — Pixel-difference harness

_Client ticket **LER-1017** (Story, To Do — foundation block) · delivering ticket: **LER-2392** · build order: story 23 of 26, stage 4._

## User Story
As the regression gate's engine, we want a tool that compares a rendered PDF against a stored reference render page by page, so that "looks the same" is an objective pass or fail with a visual diff artefact when it is not.

## Acceptance Criteria
- Given a render and its baseline, when compared, then pages are rasterised at a fixed DPI and diffed pixel-wise with a small anti-aliasing tolerance; a mismatch fails with the page number, the differing-pixel count, and a written diff image.
- Given a page-count difference, when compared, then that alone is a failure before any pixels are diffed.
- Given the tool (`tools/pixel-diff`, the orphan-scan conventions: report / `--json` / `--quiet`, exit 1 on drift), when it ships, then it carries self-tests — identical inputs pass, a doctored fixture fails on the right page.

## Notes & Constraints
- Rasterisation through the same pinned Chromium (render the PDF pages to images) — no new native imaging dependency unless the story proves it necessary; record the choice in the PR body.
- The tolerance is a named constant with a comment, not a magic number — it will be argued about later.

## Definition of Done
- Tool + self-tests delivered; full gate set green
