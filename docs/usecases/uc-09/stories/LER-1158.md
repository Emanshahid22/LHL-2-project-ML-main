# LER-1158 — Automatic pagination

_UC-09 PDF Generation & Formatting · epic: `docs/usecases/uc-09/epic.md` · PRD: `docs/usecases/uc-09/prd.md`_

_Client ticket **LER-1158** (Story, To Do) · delivering ticket: **LER-2378** · build order: story 08 of 26, stage 2._

## User Story
As a solicitor with a lengthy MG11 narrative, we want multi-page forms paginated automatically with sane break behaviour, so that long statements produce readable documents and the page count that feeds the declaration is real.

## Acceptance Criteria
- Given a narrative long enough to span pages, when it renders, then content flows across pages with the running header/footer on every page, no clipped lines, and `page-break-inside` protection on boxes that must not split (a signature block, a single schedule row).
- Given the MG6 schedule and MG12 exhibit table, when they span pages, then the column headers repeat on each page.
- Given any multi-page render, when it completes, then the page count recorded is the paginated truth (LER-1071) and the draft band (draft-marking story) appears on every page, not just the first.

## Notes & Constraints
- Pagination rules live in the layout data / print CSS, not in per-form code — the binding stays generic.

## Definition of Done
- Delivered against the criteria; e2e covers a 1-page and an N-page render of the same form
- Full gate set green
