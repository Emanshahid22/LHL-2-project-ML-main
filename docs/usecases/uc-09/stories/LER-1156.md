## User Story
As the pixel-regression gate's supplier, we want one reference render captured per form from sanctioned fixtures, so that "the output has not drifted since a human looked at it" has a stored, versioned referent.

## Acceptance Criteria
- Given the LER-1269 fixture decision executed, when baselines are captured, then one reference render per form (11) derives only from sanctioned fixture data, is stored in-repo with the generation's template and layout versions recorded beside it, and the capture command is a repeatable script, not a manual export.
- Given a baseline, when a template or layout legitimately changes, then re-capture is deliberate (the script re-run, the diff reviewed in the PR) — never automatic.
- Given the four forms with no genuine specimen, when their baselines are captured, then the baseline records that it is a self-referent only (no fidelity claim — D2/D6 wording).

## Notes & Constraints
- D3: the client original imagined capturing from "the official template"; there is none. The baseline is our own signed-off output — which is exactly what a regression gate needs.
- Baselines from polluted fixtures are the failure LER-1269 exists to prevent; the ordering is a hard gate, not a preference.

## Definition of Done
- 11 baselines + capture script + provenance sidecars committed; full gate set green
