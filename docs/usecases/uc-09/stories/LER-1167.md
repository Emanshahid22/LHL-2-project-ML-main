# LER-1167 — Download-time filename generation

_UC-09 PDF Generation & Formatting · epic: `docs/usecases/uc-09/epic.md` · PRD: `docs/usecases/uc-09/prd.md`_

_Client ticket **LER-1167** (Story, To Do) · delivering ticket: **LER-2387** · build order: story 12 of 26, stage 2._

## User Story
As a solicitor saving a document, we want a readable filename built from database metadata at the moment of download, so that the file lands sensibly named on my machine while nothing readable is ever written to disk or a storage key on the server.

## Acceptance Criteria
- Given a download, when the response streams, then `Content-Disposition` carries a name of the proposed convention `<formCode>-<URN|standalone>-<yyyy-mm-dd>.<ext>` derived from the DB row at request time — and that string is never persisted anywhere.
- Given the filename generator, when unit-tested against the seeded fixtures, then it never emits any defendant field value or DOB-shaped fragment (the DoD 3 property applied to the one human-readable name in the system).
- Given open question Q6 (does the client read a URN as acceptable in a download name?), when unresolved, then the convention ships as proposed with the question visibly open — a one-line change either way.

## Notes & Constraints
- A URN is a case reference, not defendant personal data; the DoD's own wording ("defendant personal data") is what the property tests encode. Q6 exists so the client confirms that reading.

## Definition of Done
- Delivered against the criteria; unit property tests; e2e asserts the header and that no readable name reaches storage; full gate set green
