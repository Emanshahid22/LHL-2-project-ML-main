# LER-1162 — DOCX export

_UC-09 PDF Generation & Formatting · epic: `docs/usecases/uc-09/epic.md` · PRD: `docs/usecases/uc-09/prd.md`_

_Client ticket **LER-1162** (Story, To Do) · delivering ticket: **LER-2382** · build order: story 20 of 26, stage 3._

## User Story
As a solicitor who needs to quote or adapt a statement, we want a Word export of the form, so that editable text exists — clearly subordinated to the authoritative PDF.

## Acceptance Criteria
- Given a generated document, when "Download as Word" is clicked, then a DOCX generates from the same render model (never by converting the PDF), streams with the LER-1167 naming convention, is stored encrypted like its PDF sibling, and a `DOCX_EXPORTED` audit row records it.
- Given the DOCX, when opened, then every field label and value of the form is present in reading order, with sections as headings — fidelity of content, not of layout.
- Given the product's outputs, when described anywhere (UI, docs), then the PDF is the authoritative version and the DOCX is not — wording delivered by LER-1163's label.

## Notes & Constraints
- Generation via a small OOXML writer over the render model; no heavyweight document library unless the writer proves insufficient — decide inside the story, record the choice in the PR body.

## Definition of Done
- Delivered against the criteria; e2e opens the DOCX (unzip + XML assert) rather than trusting the extension; full gate set green
