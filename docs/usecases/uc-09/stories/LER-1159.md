# LER-1159 — In-browser preview

_UC-09 PDF Generation & Formatting · epic: `docs/usecases/uc-09/epic.md` · PRD: `docs/usecases/uc-09/prd.md`_

_Client ticket **LER-1159** (Story, To Do) · delivering ticket: **LER-2379** · build order: story 17 of 26, stage 3._

## User Story
As a solicitor, we want the generated PDF visible in the browser before any download, so that I can check the document without scattering copies onto my machine.

## Acceptance Criteria
- Given a completed job, when the preview opens, then it displays the decrypted stream from `GET /documents/:id/preview` inline — the stored bytes exactly, never a client-side re-render — behind the same access check as the draft.
- Given an unauthorised user (the UC-07 colleague fixture), when they request the preview URL directly, then they are refused and the draft's content never reaches them.
- Given the preview, when it renders an unverified template's document, then the draft band is visible on it — what is previewed is what is stored.

## Notes & Constraints
- `<iframe>` on the preview endpoint; the browser's native PDF viewer does the heavy lifting. Explicit controls are LER-1160's story.

## Definition of Done
- Delivered against the criteria; direct-URL refusal check; full gate set green
