_Client ticket **LER-1157** (Story, To Do) · delivering ticket: **LER-2377** · build order: story 24 of 26, stage 4 · **deviation D3**._

## User Story
As the build, we want every form's fresh render compared against its committed baseline on every CI run, so that layout drift — a CSS bump, a Chromium update, a binding change — fails loudly instead of shipping quietly.

## Acceptance Criteria
- Given CI, when it runs, then each of the 11 forms renders from the sanctioned fixtures and is compared to its baseline with LER-1017's harness; any drift fails the build with the diff artefacts uploaded (the trace-upload pattern).
- Given a deliberate layout change, when its PR re-captures baselines (LER-1156's script), then the gate passes and the PR's diff shows exactly which pages changed — drift becomes reviewable.
- Given a Chromium version bump, when it lands, then this gate is the thing that decides whether it changed output — recorded as the gate's explicit second job.

## Notes & Constraints
- D3: the comparison is self-baseline regression, not official-template fidelity — DoD 1's open status (D6) is not softened by this gate's existence, and no doc may imply it is.
- CI wall-clock: renders reuse one warm browser; budget measured and recorded in the PR.

## Definition of Done
- CI step delivered, red-path proven with a doctored fixture; full gate set green
