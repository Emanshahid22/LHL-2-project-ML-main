# LER-1073 — Page-count assertion: declared and actual must agree

_UC-09 PDF Generation & Formatting · epic: `docs/usecases/uc-09/epic.md` · PRD: `docs/usecases/uc-09/prd.md`_

_Client ticket **LER-1073** (Story, To Do — deferred from UC-03) · delivering ticket: **LER-2396** · build order: story 09 of 26, stage 2._

## User Story
As the render pipeline's last gate, we want generation to fail when the declaration's interpolated page count and the actual page count disagree, so that a statement declaring three pages while four were generated can never be stored or handed to a user.

## Acceptance Criteria
- Given interpolation active (post-LER-1200) and a count mismatch induced in a test, when generation runs, then the job fails with a reason naming both counts, nothing is stored, and the failure is audited.
- Given interpolation inactive (today's shipped wording), when generation runs, then the assertion is a no-op that still executes — the wiring is proven before the wording decision, not after.
- Given unit tests, when they run, then match, mismatch and inactive cases are covered.

## Notes & Constraints
- A failed assertion is a defect signal, not a user warning — deliberately blocking (the client ticket's own rationale).

## Definition of Done
- Delivered against the criteria; the induced-mismatch path has an e2e check; full gate set green
