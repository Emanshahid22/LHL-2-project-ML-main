## User Story
As a defence solicitor, I want each form field mapped to the case datum it actually is, so that auto-fill never puts the right value in the wrong box or the wrong person in the right box.

## Acceptance Criteria
- Given a template field that corresponds to a case datum, when the template declares `mapsTo`, then the path is one of the closed set of case field paths and resolves in exactly one place.
  - Covered by: e2e/mg4-charge-sheet.spec.ts › `no field maps case data to something that is not that datum`
- Given a form with both mapped and unmapped fields, when auto-fill runs, then exactly the mapped fields are written and nothing else is touched.
  - Covered by: e2e/mg4-charge-sheet.spec.ts › `auto-fill populates exactly the mapped fields and nothing else`
- Given MG16's `subjectName`, when auto-fill runs, then it is not filled from the defendant, because a s.100 notice concerns a non-defendant.
  - Covered by: e2e/uc02-autofill.spec.ts › `MG16 subjectName is not auto-filled from the defendant`
- Given MG11, when a case-linked draft opens, then no witness field auto-fills from the case — a witness is not the defendant.
  - Covered by: e2e/uc03-mg11-wizard.spec.ts › `UC-02 is unchanged: witness fields never auto-fill from the case`
- Given a case with several offences, when the charges path resolves, then every offence's charge wording is included rather than the first one only.
  - Covered by: e2e/uc02-autofill.spec.ts › `charges are joined from every offence on the case`

## Notes & Constraints

- `CaseFieldPath` is a closed union, so a typo is a compile error; `npm run conformance` additionally
  rejects a `mapsTo` that is not a real path.
- Eight of the eleven templates carry mappings (MG4 8, MG3 6, MG1 5, MG5 5, MG16 3, MG12 2, MG15 2,
  MG2 1). MG11 and MG6 carry none, deliberately in MG11's case.

- Resolver: `libs/shared/src/lib/autofill.ts` (pure). Service: `apps/api/src/drafts/drafts.service.ts`.
  Badges and notes: `apps/web/src/app/shared/dynamic-form/dynamic-form.ts`.
- **`mapsTo` only where the case datum genuinely IS the field.** An MG11 witness is not the defendant;
  MG16 `subjectName` stays unmapped pending a legal ruling. Never map signatures or non-OIC officers.
- Provenance matching is a `JSON.stringify` comparison, so dates must stay ISO strings in controls —
  `provideNativeDateAdapter` would silently kill every badge (CLAUDE.md rule 7).
- **Additive only:** a field id is permanent; `valuesJson` and `autoFillJson` are both keyed by id.
