## User Story
As a defence solicitor, I want a one-line summary of what auto-fill managed, so that I know how much of the form is still mine to complete before I start reading it.

## Acceptance Criteria
- Given a population run, when it completes, then a summary states how many of the mappable fields were filled.
  - Covered by: e2e/uc02-autofill.spec.ts › `first open of a case-linked draft populates and summarises`
- Given the summary, when I dismiss it, then it goes and does not return for that session.
  - Covered by: e2e/uc02-autofill.spec.ts › `the summary can be dismissed`
- Given a template with unmapped fields, when the summary counts, then its denominator is the mappable fields only, not every field on the form.
  - Covered by: e2e/uc02-autofill.spec.ts › `the summary counts only mappable fields`

## Notes & Constraints

- The denominator matters: counting all fields would make every form read as mostly unfilled and the
  number would carry no information. "3 of 5 mappable fields" is a claim about what auto-fill could ever
  have done.
- The summary also tells the user to review each value — it does not present the fill as authoritative.

- Resolver: `libs/shared/src/lib/autofill.ts` (pure). Service: `apps/api/src/drafts/drafts.service.ts`.
  Badges and notes: `apps/web/src/app/shared/dynamic-form/dynamic-form.ts`.
- **`mapsTo` only where the case datum genuinely IS the field.** An MG11 witness is not the defendant;
  MG16 `subjectName` stays unmapped pending a legal ruling. Never map signatures or non-OIC officers.
- Provenance matching is a `JSON.stringify` comparison, so dates must stay ISO strings in controls —
  `provideNativeDateAdapter` would silently kill every badge (CLAUDE.md rule 7).
- **Additive only:** a field id is permanent; `valuesJson` and `autoFillJson` are both keyed by id.
