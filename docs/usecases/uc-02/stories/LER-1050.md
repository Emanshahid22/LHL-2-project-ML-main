## User Story
As a defence solicitor, I want anything I typed to be untouchable by auto-fill, so that re-running it can never cost me my own work.

## Acceptance Criteria
- Given a field I typed by hand, when auto-fill runs again, then my value is left exactly as it is.
  - Covered by: e2e/uc02-autofill.spec.ts › `population never overwrites a manual value on re-run`
- Given a field I cleared back to empty, when auto-fill runs again, then it is refilled — an empty field is fair game.
  - Covered by: e2e/uc02-autofill.spec.ts › `re-run refills a field that was cleared back to empty`
- Given a field I edited, when I reload the page, then it is still manual rather than reverting to auto-filled.
  - Covered by: e2e/uc02-autofill.spec.ts › `editing a filled field makes it manual, and it stays manual across a reload`
- Given the scope's DoD phrase "without overwriting non-matching fields", when the suite runs, then a check proves the manual value survives.
  - Covered by: e2e/uc02-autofill.spec.ts › `population never overwrites a manual value on re-run`

## Notes & Constraints

- The mechanism is the **pristine test**: a field is written only when it is empty, or when
  `JSON.stringify(current) === JSON.stringify(provenance.value)` — i.e. it still holds exactly what a
  previous run wrote. Anything else is a human's value.
- This is the rule the whole use case is built around; both directions are asserted, because a rule that
  only ever refuses to write would pass a one-sided test.

- Resolver: `libs/shared/src/lib/autofill.ts` (pure). Service: `apps/api/src/drafts/drafts.service.ts`.
  Badges and notes: `apps/web/src/app/shared/dynamic-form/dynamic-form.ts`.
- **`mapsTo` only where the case datum genuinely IS the field.** An MG11 witness is not the defendant;
  MG16 `subjectName` stays unmapped pending a legal ruling. Never map signatures or non-OIC officers.
- Provenance matching is a `JSON.stringify` comparison, so dates must stay ISO strings in controls —
  `provideNativeDateAdapter` would silently kill every badge (CLAUDE.md rule 7).
- **Additive only:** a field id is permanent; `valuesJson` and `autoFillJson` are both keyed by id.
