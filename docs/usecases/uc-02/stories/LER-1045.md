## User Story
As a defence solicitor, I want to see at a glance which values the machine supplied, so that I know exactly which boxes still need my eyes on them.

## Acceptance Criteria
- Given a field auto-fill has filled, when the form renders, then it carries an "Auto-filled" badge and a Clear affordance.
  - Covered by: e2e/uc02-autofill.spec.ts › `filled fields carry an Auto-filled badge with a Clear affordance`
- Given an auto-filled date, when it renders in UK format, then it still carries its badge — reformatting for display does not count as an edit.
  - Covered by: e2e/uk-dates.spec.ts › `an auto-filled date shows UK format and keeps its badge`
- Given a reload, when the form re-renders, then badges are restored from stored provenance rather than being lost.
  - Covered by: e2e/uc02-autofill.spec.ts › `editing a filled field makes it manual, and it stays manual across a reload`

## Notes & Constraints

- The badge is **computed, never stored**: `isAutoFilled()` compares the live control value with the
  stored provenance value on every change, so it always describes the value currently on screen.
- That comparison is why a `Date` object in a control would remove every badge silently.
- **Coverage gap:** the scope criterion says the badge appears on *every* pre-filled field; the suite
  asserts it on a filled field rather than looping over the run's `filled` outcomes. Recorded as
  `open-questions.md` G2, which is why that criterion is **Partial** in `docs/acceptance-mapping.md`.

- Resolver: `libs/shared/src/lib/autofill.ts` (pure). Service: `apps/api/src/drafts/drafts.service.ts`.
  Badges and notes: `apps/web/src/app/shared/dynamic-form/dynamic-form.ts`.
- **`mapsTo` only where the case datum genuinely IS the field.** An MG11 witness is not the defendant;
  MG16 `subjectName` stays unmapped pending a legal ruling. Never map signatures or non-OIC officers.
- Provenance matching is a `JSON.stringify` comparison, so dates must stay ISO strings in controls —
  `provideNativeDateAdapter` would silently kill every badge (CLAUDE.md rule 7).
- **Additive only:** a field id is permanent; `valuesJson` and `autoFillJson` are both keyed by id.
