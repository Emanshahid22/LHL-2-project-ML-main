## User Story
As a defence solicitor, I want to accept, change or remove any auto-filled value individually, so that I remain responsible for every word on a document I sign.

## Acceptance Criteria
- Given an auto-filled field, when I clear it, then the value goes and the badge goes with it.
  - Covered by: e2e/uc02-autofill.spec.ts › `clearing a filled field makes it manual and drops the badge`
- Given an auto-filled field, when I edit it, then it becomes a manual value and the badge disappears immediately.
  - Covered by: e2e/uc02-autofill.spec.ts › `editing a filled field makes it manual, and it stays manual across a reload`
- Given I have edited an auto-filled field, when the draft is saved, then the server drops that field's provenance so it is manual server-side too.
  - Covered by: e2e/uc02-autofill.spec.ts › `saving a value that differs from what auto-fill wrote prunes its provenance`
- Given I accept a value by leaving it alone, when I continue, then no separate confirmation step is required of me.
  - Covered by: e2e/uc02-autofill.spec.ts › `filled fields carry an Auto-filled badge with a Clear affordance`

## Notes & Constraints

- There is deliberately **no explicit "accept" action**. Acceptance is the absence of a change; adding a
  per-field confirm would be a click per field with no information gained.
- The scope's "all confirmed values locked" step was **not** built — a draft stays editable. See
  `open-questions.md` D2.

- Resolver: `libs/shared/src/lib/autofill.ts` (pure). Service: `apps/api/src/drafts/drafts.service.ts`.
  Badges and notes: `apps/web/src/app/shared/dynamic-form/dynamic-form.ts`.
- **`mapsTo` only where the case datum genuinely IS the field.** An MG11 witness is not the defendant;
  MG16 `subjectName` stays unmapped pending a legal ruling. Never map signatures or non-OIC officers.
- Provenance matching is a `JSON.stringify` comparison, so dates must stay ISO strings in controls —
  `provideNativeDateAdapter` would silently kill every badge (CLAUDE.md rule 7).
- **Additive only:** a field id is permanent; `valuesJson` and `autoFillJson` are both keyed by id.
