## User Story
As a defence solicitor, I want conflicting case data reported rather than resolved, so that the machine never quietly picks one of two offence dates for me.

## Acceptance Criteria
- Given a case with two different offence dates, when the offence-date field resolves, then it is left blank with a note saying two dates exist and to choose manually.
  - Covered by: e2e/uc02-autofill.spec.ts › `ambiguous case data leaves the field blank with an explanatory note`
- Given an ambiguous outcome, when the API reports it, then the reason names the conflict rather than saying only "ambiguous".
  - Covered by: e2e/uc02-autofill.spec.ts › `ambiguous and no_data outcomes are reported with reasons`
- Given the scope requires this tested against duplicate offence entries, when the suite runs, then it uses the seeded two-offence case rather than a synthetic stub.
  - Covered by: e2e/uc02-autofill.spec.ts › `ambiguous case data leaves the field blank with an explanatory note` (Marcus Bellamy, two offences)

## Notes & Constraints

- `resolveCaseField` returns a three-way result — `value | ambiguous | no_data` — so "cannot decide"
  is a first-class outcome in the type system, not an empty string that looks like missing data.
- The `charges` path is deliberately **not** ambiguous with several offences: every charge belongs on the
  form, so they are joined rather than treated as competing candidates.

- Resolver: `libs/shared/src/lib/autofill.ts` (pure). Service: `apps/api/src/drafts/drafts.service.ts`.
  Badges and notes: `apps/web/src/app/shared/dynamic-form/dynamic-form.ts`.
- **`mapsTo` only where the case datum genuinely IS the field.** An MG11 witness is not the defendant;
  MG16 `subjectName` stays unmapped pending a legal ruling. Never map signatures or non-OIC officers.
- Provenance matching is a `JSON.stringify` comparison, so dates must stay ISO strings in controls —
  `provideNativeDateAdapter` would silently kill every badge (CLAUDE.md rule 7).
- **Additive only:** a field id is permanent; `valuesJson` and `autoFillJson` are both keyed by id.
